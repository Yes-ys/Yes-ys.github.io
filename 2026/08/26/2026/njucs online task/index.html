C/C++

基础核心

指针：存放内存地址的变量。
解引用（）：通过地址取到那间“屋子”里的值。
取地址（&）：获取变量在内存中的门牌号。
指针的类型：决定了指针加减 1 时跳过多少个字节（int 跳 4 字节，double* 跳 8 字节）。

数组指针

指针数组 int *p[5]：[ ] 优先级高于 *，所以 p 是一个数组，里面有 5 个 int* 指针。
数组指针 int (*p)[5]：(*p) 说明 p 是个指针，它指向一个包含 5 个 int 元素的整个数组，[5]实际上是类型声明的一部分。

注意点：

  1. 指针数组每个元素是指向该数组元素的指针 数组指针是指向一个数组的指针
  2. 数组指针的步长是 数组元素的字节数*数组元素的个数
  3. 典型的数组指针的应用场景是在二维数组中，例如int matrix[3][4]; int (*row)[4] = matrix;，用来指向二维数组中一维的指针；

函数指针

函数指针指向的是代码段的首地址，主要用于回调函数（如 qsort）、状态机或实现多态。

函数指针的例子：

int add(int a, int b) { return a + b; }

int main() {
    // 赋值：函数名就是地址，& 可加可不加
    int (*func_ptr)(int, int) = add; 
    // 调用：两种写法等价（C++ 中推荐直接 func_ptr(a,b)）
    int result = func_ptr(3, 5);   
    // 或者 int result = (*func_ptr)(3, 5);
    // 如果单纯声明函数指针就使用int (*f)(int,int); 即声明了一个接受 返回类型为int 参数列表为(int,int)类型函数 的指针f，f是变量名
}

C++中可以使用using别名

using FuncType = void(*)(int); // 定义类型别名
void forEach(int* arr, int n, FuncType f) { ... } // 作为参数传递
//注意，这里的FuncType是定义了一个函数指针的类型
void(*f)(int);//这是定义了一个函数指针变量，和上面的类型不同，等价于FuncType f;

函数指针通常可以用于复杂解析式的声明（要使用右左法则），下例是返回函数指针的函数

void (*signal(int sig, void (*func)(int)))(int);
//这是一个函数声明：signal 接受 (int, 函数指针)，返回一个函数指针（指向返回 void、接受 int 的函数）。
//为了让代码可读性强，通常先声明一个函数指针的类型
using FuncType = void(*)(int);
FuncType signal(int sig,Func f);

返回函数指针的函数和函数指针的声明很像，要注意区分

右左法则：先向右看（Right），再向左看（Left），遇到括号跳出去，重复这个过程。（主要是帮助读懂声明的“标识符”的含义）；

例如对于上述复杂解析式：

  1. 找到标识符：找到 signal。
  2. 向右看：遇到 (，说明 signal 是一个函数，参数是 (int sig, void (*func)(int))。
  3. 向左看：跳过 ) 后，遇到 *，说明这个函数返回的是一个指针。
  4. 跳出括号：继续向右看，遇到 (int)，说明这个指针指向一个函数，该函数接受 int，返回 void。

函数指针的一个应用场景：系统级信号/中断处理（如 signal 本身）这是该语法诞生的初衷。操作系统需要允许用户动态替换或恢复某个信号的处理逻辑，同时返回旧的处理函数指针以供备份。

简单的示例代码：

#include <stdio.h>

typedef void (*sighandler_t)(int);

static sighandler_t handler_table[10] = {NULL};

// 为每个包装器分配独立的“下一个”指针
static sighandler_t g_log_next = NULL;   // 日志层专用
static sighandler_t g_auth_next = NULL;  // 鉴权层专用

sighandler_t my_signal(int sig, sighandler_t func) {
    if (sig < 0 || sig >= 10) return NULL;
    sighandler_t old = handler_table[sig];
    handler_table[sig] = func;
    return old;
}

void trigger_signal(int sig) {
    if (handler_table[sig] != NULL)
        handler_table[sig](sig);
}

// ---------- 具体处理函数 ----------
void handle_business(int sig) {
    printf("  [业务层] 执行核心交易逻辑，信号: %d\n", sig);
}

// 日志包装器：调用自己的 g_log_next
void log_wrapper(int sig) {
    printf("  [日志层] 开始记录...\n");
    if (g_log_next) g_log_next(sig);   // 指向业务处理
    printf("  [日志层] 记录结束。\n");
}

// 鉴权包装器：调用自己的 g_auth_next
void auth_wrapper(int sig) {
    printf("  [鉴权层] 验证用户权限...\n");
    if (g_auth_next) g_auth_next(sig); // 指向日志包装器
    printf("  [鉴权层] 权限验证通过。\n");
}

int main() {
    // 1. 注册核心业务函数
    my_signal(1, handle_business);
    printf(">>> 注册业务函数完成\n");

    // 2. 构建 日志 → 业务
    g_log_next = handle_business;      // 日志的“下一个”设为业务
    my_signal(1, log_wrapper);         // 此时表[1] = log_wrapper
    printf(">>> 注册日志包装器完成\n");

    // 3. 构建 鉴权 → 日志 → 业务
    g_auth_next = log_wrapper;         // 鉴权的“下一个”设为当前的日志包装器
    my_signal(1, auth_wrapper);        // 此时表[1] = auth_wrapper
    printf(">>> 注册鉴权包装器完成\n");

    // 最终触发
    printf("\n>>> 触发信号 1（执行完整链条）：\n");
    trigger_signal(1);

    // 调用链：auth_wrapper → g_auth_next (log_wrapper) 
    //       → log_wrapper → g_log_next (handle_business)
    // 每个包装器只认自己专属的 next 指针，绝不会互相覆盖或递归。
    return 0;
}

多重指针

存放指针的地址。每多一级 *，就多一层间接寻址。

一级指针 int *p：指向普通变量。
二级指针 int **pp：指向一级指针

例子：

int a = 10;
int *p = &a;   // 一级：p存a的地址
int **pp = &p; // 二级：pp存p的地址

**pp == 10; // 解引用两次：*pp 拿到 p 的值（即a的地址），再 * 拿到 a 的值

常见的应用场景：

  1. 在函数内修改函数外的指针本身（不只是改所指内容）：
void allocate_memory(int **ptr) { // 传入指针的地址
    *ptr = (int*)malloc(sizeof(int)); // 修改外部的指针指向
    **ptr = 100;
}
int *p = NULL;
allocate_memory(&p); // 传 p 的地址
  1. 字符串数组（数组的元素是字符串）
char *argv[] = {"ls", "-l", NULL}; // 指针数组，argv本身也是二级指针
// main 函数的 int main(int argc, char **argv) 
// argv 就是二级指针，argc 是长度，argv[0] 指向 "ls"

数组与指针

数组名退化和不退化的情况

数组名与指针的关系：数组名可以退化为指针，但不是所有时候都会退化

  1. 使用数组名直接赋值指针的时候、传递数组名的时候，通常会退化；
  2. 使用sizeof、&的时候不会退化
int arr[5] = {1, 2, 3, 4, 5};

//sizeof
printf("%zu\n", sizeof(arr)); // 输出 20 (5 * 4 字节) —— 这是整个数组的大小
printf("%zu\n", sizeof(arr[0])); // 输出 4

//退化
// 关键：只有在表达式中使用时，数组名才会"退化"为指向首元素的指针
int *p = arr; // 此时 arr 退化成 &arr[0]
printf("%zu\n", sizeof(p)); // 输出 8（64位系统下指针大小，不再是20！）

//&
printf("arr    = %p\n", arr);     // 假设输出 0x100
printf("arr + 1 = %p\n", arr + 1); // 输出 0x104（+4字节）
    
printf("&arr   = %p\n", &arr);    // 输出 0x100（数值相同）
printf("&arr + 1 = %p\n", &arr + 1); // 输出 0x114（+20字节）
return 0;

传递数组名，导致数组名退化为指针（也就是说本质是传递的指针，因此在传递数组的时候通常要附上数组的长度作为参数）

// 下面这三种写法在编译器中完全等价，都是 int *arr
void test(int arr[5]) { sizeof(arr); } // 结果是 8，不是 20！
void test(int arr[])  { sizeof(arr); } // 结果是 8
void test(int *arr)   { sizeof(arr); } // 结果是 8

多维数组

int matrix[3][4] 本质是一个数组，里面有 3 个元素，每个元素是一个 包含 4 个 int 的一维数组。

内存布局是行主序（Row-major）：[行0][列0] → [行0][列1] → … → [行1][列0] … 连续存储。

多维数组的退化（非常重要）：

matrix 退化为指向 第一行 的指针，即 int ()[4]（步长是 4 个 int，即16字节）。
matrix[0] 退化为指向 第一行第一列 的指针，即 int（步长是 4 字节）。

int matrix[3][4];
int (*row)[4] = matrix;     // 正确，指向第一行
int *col = matrix[0];        // 正确，指向首个元素
// int **ptr = matrix;       // 错误！类型不匹配，int** 和 int(*)[4] 完全不同！

内存分区

C/C++程序在运行时，其占用的内存空间会被逻辑地划分为若干个具有不同属性与生命周期的区域。

代码区 (Code Segment / Text Segment)

代码区，亦称文本段，用于存放程序编译后生成的CPU机器指令，即函数体的二进制代码。该区域具备两个关键特性：

只读性 (Read-Only)：为防止程序因意外或恶意操作而修改其自身指令，代码区被设定为只读。
共享性 (Shared)：对于被多个进程同时执行的同一程序（如动态链接库），操作系统只需在内存中保留一份代码区的副本供所有进程共享，从而有效节省内存资源。

代码区的内存在程序运行前即被加载，并贯穿整个程序的生命周期。

全局/静态存储区 (Global/Static Storage)

此区域用于存放全局变量和静态变量（即被static关键字修饰的变量）。该区域的内存在程序开始时被分配，并在程序结束时由操作系统统一释放。

在传统的C语言实现中，该区域会根据变量是否被显式初始化，进一步细分为.data段（已初始化）和.bss段（未初始化）。然而，在现代C++标准中，这种区分在逻辑上通常不再被强调，二者被统一视为全局/静态存储区的一部分。

常量存储区 (Constant Storage)

常量存储区用于存放编译期间即可确定的常量数据，典型的例子包括字符串字面量（如”hello world”）和用const修饰的全局常量。此区域通常也是只读的，任何修改该区域数据的尝试都将在运行时引发段错误（Segmentation Fault）。该区域的数据同样在程序结束后由系统释放。

栈区 (Stack)

栈区是用于管理函数调用过程的内存区域。其内存在编译器需要时自动分配，并在函数执行完毕后自动释放。栈区的管理方式类似于数据结构中的栈，遵循后进先出（LIFO, Last-In-First-Out） 的原则。

栈区主要存储以下数据:

函数的参数值（形参）。
函数内部定义的局部变量（包括const修饰的局部常量）。
函数调用后的返回地址等信息。

栈的大小在程序编译时通常是固定的（例如在Windows环境下通常为1MB或2MB）。若申请的空间超过栈的剩余容量，将引发栈溢出（Stack Overflow） 错误。

堆区 (Heap)

堆区是用于动态内存分配的区域。程序员通过malloc（C语言）或new（C++语言）等操作符申请的内存即来源于此。堆区内存的分配与释放由程序员显式控制（使用free或delete）。若程序员未主动释放，则需依赖程序结束时操作系统进行回收。

与栈区不同，堆区的内存空间通常是不连续的，其管理依赖于操作系统维护的空闲内存链表。这种分配方式也决定了堆区能够申请到的内存空间通常比栈区更大、更灵活。然而，动态内存分配的效率相对较低，且若管理不当（如忘记释放），极易导致内存泄漏（Memory Leak）。

static

前置底层概念：

存储期（Storage Duration）：决定变量在内存中存活的时长。
1 .自动存储期：栈上分配，进入作用域创建，离开作用域销毁。
2. 静态存储期：全局静态区分配，程序启动时创建，程序结束才销毁。

链接属性（Linkage）：决定变量/函数在多个编译单元（.c/.cpp 文件）中能否被访问。

  1. 无链接：只在当前代码块内有效。
  2. 内部链接：只在当前编译单元（当前 .c/.cpp 文件）内有效，其他文件无法访问。
  3. 外部链接：可被整个项目的其他编译单元访问（如全局变量）。

static 的本质作用就是干预这两者：要么把存储期改为静态，要么把链接属性改为内部。

在纯C环境中，static 有且仅有三种使用场景：

  1. 修饰局部变量（改变存储期）
  • 表现：变量存储在静态区，生命周期贯穿整个程序运行。
  • 特性：只初始化一次（首次执行到定义处），多次调用间保持值不变。
  • 作用域：依然受块作用域限制（只在花括号 {} 内可见）。
    void counter() {
    static int count = 0; // 只初始化一次，默认初始化为0
    count++;
    printf("%d ", count);
}
// 多次调用输出：1 2 3 4 ... ，而不会重新从0开始，这也是最经典的用法——“生成唯一序列号”

//还可以用于“懒加载”，例如用static初始化函数调用中的随机数生成器，让其只初始化一次，避免每次调用都初始化
    底层注意：编译时，该变量已被分配在 .data 或 .bss 段，函数调用时的汇编指令直接操作固定内存地址，而非栈指针偏移。
  1. 修饰全局变量（改变链接属性）
  • 表现：在文件顶层（所有函数之外）定义。
  • 特性：将默认的外部链接改为内部链接。
  • 效果：该变量仅在当前编译单元（当前 .c 文件）中可见。其他文件即使使用 extern 声明，也无法链接到这个变量。
// file_a.c
static int hidden_global = 100; // 仅 file_a.c 可见
// file_b.c
extern int hidden_global; // 编译通过，但链接时找不到该符号，报错 undefined reference
  1. 修饰函数（改变链接属性）
  • 表现：和修饰全局变量完全一样，将函数的默认外部链接改为内部链接。
  • 效果：该函数仅限本文件内部调用，防止与其他文件中的同名函数冲突。这是 C 语言实现封装和模块化的最原始手段
// math_utils.c
static int add_internal(int a, int b) { return a + b; } // 内部工具函数，不对外暴露
int public_add(int a, int b) { return add_internal(a, b); }

C++中static：C++ 保留了 C 的所有用法，但引入了类（Class），因此 static 在类中有全新的语义。此时 static 不再干预链接属性，而是表明该成员属于类本身，而非类的具体对象。

  1. 静态成员变量（类内声明，类外定义）
  • 本质：该变量被所有类对象共享，存储在静态区，不占用任何对象的内存空间。
  • C++17 关键变化：如果使用 inline 修饰，允许在类内直接初始化且无需在类外单独定义。
class MyClass {
public:
    static int value;      // 声明，需在类外定义
    static inline int count = 10; // C++17 起，直接定义并初始化
};
int MyClass::value = 5; // 必须在全局作用域显式定义（分配存储）
  1. 静态成员函数（无 this 指针）
  • 本质：属于类，不属于对象。
  • 限制：只能访问静态成员变量或其他静态成员函数；不能访问非静态成员（因为没有 this，不知道操作哪个对象）。
  • 用途：工厂函数、工具类、单例模式中的 getInstance()。

C++11 起：staic的作用还有局部静态变量的线程安全初始化（Magic Static）

  • 在 C 语言中，多线程同时首次调用包含静态局部变量的函数，可能导致多次初始化或数据竞争。
  • C++11 标准规定：局部 static 变量的初始化是线程安全的。编译器会插入互斥锁机制，保证第一个线程初始化完成前，其他线程阻塞等待。
// 线程安全的单例模式（Meyers' Singleton）
Singleton& getInstance() {
    static Singleton instance; // C++11 保证只初始化一次，且线程安全
    return instance;
}

const与mutable

在 C++ 中，成员函数隐含一个指向当前对象的 this 指针。

普通函数：this 类型是 ClassName*（可修改对象）。

const 成员函数：this 类型被限定为 const ClassName*（只读对象）。

因此，在 const 函数内部，编译器会禁止修改任何非 mutable 的成员变量。

如果确实需要在 const 函数中修改某个成员变量（比如缓存计算结果、统计调用次数、互斥锁），可以用 mutable 关键字修饰该变量。

补充常函数 由const修饰的函数，注意点如下：

  1. 常对象（const object）：只能调用常成员函数。如果试图调用非常成员函数，编译器会直接报错（因为非常函数可能修改对象，违背了常对象的常量性）。
  2. 非常对象（non-const object）：可以调用常成员函数，也可以调用非常成员函数。调用哪个取决于函数重载匹配。
  3. 由const修饰已有的函数写一个新函数（除了新增了const修饰以外，其他函数名、参数列表等都相同），也算重载

运行时多态-虚函数

C++ 虚函数是实现运行时多态（Run-time Polymorphism）的核心机制。它允许程序在运行时，根据对象的实际类型来决定调用哪个函数，而不是仅仅根据指针或引用的声明类型。

虚函数的使用&运行时多态的例子

#include <iostream>
using namespace std;

class Base {
public:
    virtual void speak() { 
        cout << "I am Base" << endl; 
    }
};

class Derived : public Base {
public:
    // 重写虚函数（C++11 建议加 override）
    void speak() override { 
        cout << "I am Derived" << endl; 
    }
};

// 全局函数，接受基类引用
void makeItSpeak(Base& obj) {
    obj.speak(); // 这里发生动态绑定
}

int main() {
    Derived d;
    makeItSpeak(d); // 输出：I am Derived

    Base* ptr = new Derived();
    ptr->speak();   // 输出：I am Derived
    delete ptr;

    return 0;
}

//obj.speak() 在编译时无法确定调用哪个版本，运行时通过 d 和 ptr 对象内部的 vptr 找到 Derived 的虚函数表，从而执行正确的函数。

主流编译器（如 GCC、Clang、MSVC）普遍采用基于虚函数表（vtable） 和虚函数指针（vptr） 的模型。

虚函数表 (vtable)：每个包含（或继承）虚函数的类，在编译时都会生成一个唯一的虚函数表。这个表本质上是一个函数指针数组，按声明顺序存储了该类所有虚函数的地址。它是类级别的，同一个类的所有对象共享同一个虚函数表。

虚函数指针 (vptr)：每个包含虚函数的对象，其内存布局中都会有一个隐藏的指针（vptr），指向该类对应的虚函数表。vptr 是对象级别的，在对象构造时由编译器自动初始化。

虚函数在构造和析构期间会“失活”，此时调用的永远是当前正在构造/析构的类自身的版本。

#include <iostream>
using namespace std;

class Base {
public:
    Base() { 
        speak(); // 危险调用
    }
    virtual void speak() { 
        cout << "Base speak" << endl; 
    }
};

class Derived : public Base {
public:
    Derived() { 
        speak(); 
    }
    void speak() override { 
        cout << "Derived speak" << endl; 
    }
};

int main() {
    Derived d; 
    // 输出顺序：
    // Base speak  (构造 Base 时，Derived 还没构造完，vptr 指向 Base 的表)
    // Derived speak (构造 Derived 时，vptr 已被修正为指向 Derived 的表)
    return 0;
}

virtual/override/final

override：明确告诉编译器“我在重写基类的虚函数”。如果基类没有对应虚函数，或函数签名不匹配，编译器会报错，防止手滑写错（比如把 speak 写成 speek 导致悄悄重载而不是重写）。

final：阻止派生类继续重写该虚函数。

纯虚函数

纯虚函数（Pure Virtual Function）是 C++ 实现抽象接口的基石

含有纯虚函数的类称为抽象类（Abstract Class），它不能实例化，只能作为基类使用。

#include <iostream>
using namespace std;

// 定义一个接口/抽象类
class Shape {
public:
    // 纯虚函数：声明末尾加 = 0
    virtual double area() const = 0; 
    
    // 普通虚函数（可选）：提供默认实现，派生类可以重写也可以不重写
    virtual void info() const {
        cout << "This is a shape" << endl;
    }
};

class Circle : public Shape {
private:
    double radius;
public:
    Circle(double r) : radius(r) {}
    
    // 必须实现 area()，否则 Circle 也变成抽象类，无法实例化
    double area() const override {
        return 3.14159 * radius * radius;
    }
};

int main() {
    // Shape s; // 编译错误！不能创建抽象类的对象
    Circle c(5.0);
    cout << c.area() << endl; // 输出 78.5397
    
    Shape* ptr = new Circle(3.0);
    cout << ptr->area() << endl; // 动态绑定，调用 Circle::area()
    delete ptr;
    return 0;
}

纯虚析构函数

当你将析构函数声明为纯虚函数时，必须在类外部提供它的实现（函数体），否则链接会报错。

派生类对象析构时，无论基类析构函数是否纯虚，最终一定会调用基类的析构函数。如果编译器找不到基类析构的函数体，就无法完成析构链。

#include <iostream>
using namespace std;

class Base {
public:
    // 声明为纯虚析构，目的是让 Base 成为抽象类（且不占用额外空间）
    virtual ~Base() = 0; 
};

// 必须提供实现！否则链接器报错 "undefined reference to `Base::~Base()'"
Base::~Base() {
    cout << "Base destructor called" << endl;
}

class Derived : public Base {
public:
    ~Derived() override {
        cout << "Derived destructor called" << endl;
    }
};

int main() {
    Base* p = new Derived();
    delete p; 
    // 输出顺序：
    // Derived destructor called
    // Base destructor called
    return 0;
}

模板

C++ 模板（Template）是一种强大的编译时泛型编程工具，它允许你编写与类型无关的代码，从而实现代码复用、类型安全和运行时效率（因为所有实例化都在编译期完成）。

常见的使用有两种：

  1. 函数模板
  2. 类模板

函数模板的例子

#include <iostream>
using namespace std;

// 定义一个交换两个值的函数模板
template <typename T>
void mySwap(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 10, y = 20;
    mySwap(x, y);          // 实例化为 int 版本
    cout << x << " " << y << endl; // 20 10

    double p = 1.1, q = 2.2;
    mySwap(p, q);          // 实例化为 double 版本
    cout << p << " " << q << endl; // 2.2 1.1

    // 也可以显式指定类型
    mySwap<double>(p, q);  // 显式实例化
    return 0;
}

typename T 也可写作 class T，效果相同。

类型模板的例子

#include <iostream>
using namespace std;

template <typename T>
class Box {
private:
    T content;
public:
    Box(const T& val) : content(val) {}
    T get() const { return content; }
    void set(const T& val) { content = val; }
};

int main() {
    Box<int> intBox(123);
    cout << intBox.get() << endl; // 123

    Box<string> strBox("Hello");
    cout << strBox.get() << endl; // Hello

    return 0;
}

其中typename T是类型参数，用于确定模板的类型

重载

函数重载：要求同名函数的形参列表必须不同，判断依据是参数个数、参数类型或参数顺序。

  1. 返回值类型不能作为重载依据，因为调用时返回值可能被忽略，编译器无法仅凭返回值区分。
  2. const 修饰的成员函数可以重载（视为参数列表不同，因为隐式的 this 指针类型不同）。
  3. 默认参数需谨慎使用，可能引发二义性。
#include <iostream>
using namespace std;

// 1. 参数个数不同
void print(int a) { cout << "int: " << a << endl; }
void print(int a, int b) { cout << "two ints: " << a << ", " << b << endl; }

// 2. 参数类型不同
void print(double d) { cout << "double: " << d << endl; }

// 3. 参数顺序不同
void print(int a, double d) { cout << "int + double" << endl; }
void print(double d, int a) { cout << "double + int" << endl; }

// 4. 成员函数 const 重载（常见于迭代器或容器的 begin()）
class Test {
public:
    void func() { cout << "non-const" << endl; }
    void func() const { cout << "const version" << endl; } // 常对象调用此版本
};

运算符重载为自定义类型（类/结构体）提供了类似内置类型的操作语法，让代码更直观。

实现方式：可作为成员函数（左侧对象调用）或友元/全局函数（需显式传入左侧参数）。

限制：

  1. 必须至少有一个用户定义类型的参数（不能重载 int + int）。
  2. 不可重载的运算符：::（作用域）、.（成员访问）、.*（成员指针）、?:（三目）、sizeof、typeid。
  3. 不可创造新运算符（如 ** 表示幂运算不行）。
  4. 不可改变优先级、结合性或操作数个数（&& 和 || 重载后会失去短路求值特性）。
class Complex {
    double real, imag;
public:
    Complex(double r = 0, double i = 0) : real(r), imag(i) {}
    
    // 作为成员函数重载 +=
    Complex& operator+=(const Complex& other) {
        real += other.real;
        imag += other.imag;
        return *this;
    }
    
    // 作为友元函数重载 +（便于支持隐式转换）
    friend Complex operator+(const Complex& a, const Complex& b) {
        return Complex(a.real + b.real, a.imag + b.imag);
    }
    
    // 重载 << 输出流（必须是非成员）
    friend ostream& operator<<(ostream& os, const Complex& c) {
        os << "(" << c.real << ", " << c.imag << "i)";
        return os;
    }
};
// 使用时：Complex c1(1,2), c2 = c1 + 3.14; // 借助隐式转换

为什么<<必须以非成员函数重载（通常用友元函数）

  1. 这完全是由运算符重载的调用语法决定的。
  2. 当重载为成员函数时，第一个操作数（左侧参数）必须是当前类的对象（即 this）。
  3. 对于 cout << obj，左侧操作数是 std::ostream 类型的对象（cout），右侧才是你的自定义类。
  4. 你无法给 std::ostream 类添加成员函数（标准库是封闭的），所以 operator<< 只能定义为非成员函数。

补充友元函数

友元函数的主要作用：突破类的封装性，允许非成员函数访问类中的私有（private）和保护（protected）成员。

友元函数通常是在类内部声明为友元函数，然后类外实现。它可能是全局函数也可能是局部函数，取决于实现（定义）的位置

#include <iostream>
using namespace std;

namespace MySpace { // 自定义命名空间
    class Test {
    private:
        int secret = 42;
    public:
        // 情况1：友元是全局函数（定义在全局域）
        friend void globalFriend(Test& t);
        
        // 情况2：友元是命名空间中的函数（定义在 MySpace 内，但不是全局）
        friend void spaceFriend(Test& t);
    };

    // 定义在 MySpace 命名空间内的函数（它是非成员函数，但不是全局函数）
    void spaceFriend(Test& t) {
        cout << "命名空间中的友元，访问私有: " << t.secret << endl;
    }
}

// 定义在全局域的全局函数（它是非成员函数，也是全局函数）
void globalFriend(MySpace::Test& t) {
    cout << "全局友元，访问私有: " << t.secret << endl;
}

int main() {
    MySpace::Test t;
    
    globalFriend(t);      // OK，全局函数调用
    MySpace::spaceFriend(t); // OK，命名空间中的函数调用
    
    // 注意：如果在 main 里直接写 spaceFriend(t); 会因为找不到命名空间而报错
    return 0;
}

构造函数

构造函数基本的执行过程

构造函数的执行过程：

  1. 分配内存（通常由 new 表达式或栈帧分配完成，之后会调用构造函数）。
  2. 初始化列表执行（重要：此阶段发生在函数体之前）。
  3. 函数体执行（此时对象内的成员已有初值或默认值）。
class Demo {
    const int a; // const成员必须在初始化列表中赋值
    int b;
public:
    // 正确写法：使用初始化列表
    Demo(int val) : a(val), b(val * 2) { 
        // 此时a和b已经构造完成，这里只做业务逻辑
    }
    
    // 错误写法（编译报错）：
    // Demo(int val) { a = val; } // const变量赋值发生在函数体，为时已晚
    // C++11起也支持，const类型的成员变量在类中声明的时候就进行初始化
};

深入理解：初始化列表是直接构造成员变量，而函数体内的赋值是“先默认构造，再拷贝赋值”。也就是说上面的错误写法，本质上是先使用Demo()，构造了a，再尝试给a赋值，但是a是const类型，不能赋值，所以就出错了。

构造函数隐式生成

构造函数的隐式生成与替代

编译器在特定条件下会隐式生成：

  1. 默认构造函数：仅当类中没有任何用户声明的构造函数时。
  2. 拷贝/移动构造函数：按成员逐一拷贝（浅拷贝）。
  3. 析构函数。

现代C++最佳实践：如果定义了带参构造函数，默认构造函数会被自动删除。如需保留，使用 Demo() = default;

委托构造函数

委托构造函数，允许一个构造函数调用同一个类的另一个构造函数，避免代码冗余：

class Student {
    int id;
    string name;
public:
    Student(int i, string n) : id(i), name(n) {}
    Student() : Student(0, "Unknown") {} // 委托给上面的构造函数
};

如果构造函数只有一个参数，它默认充当隐式类型转换运算符。为了防止意外的类型转换，必须加 explicit：

单参构造函数默认是隐式类型转换的“入口”

class Box {
public:
    explicit Box(int size) { /* ... */ } // 加explicit
};
void func(Box b);
func(10); // 编译报错（如果没加explicit，此处会隐式将10转为Box，容易产生Bug）
func(Box(10)); // 必须显式构造，安全

拷贝构造函数

拷贝构造用于“从已存在的对象生成一个新对象”。编译器默认生成的拷贝构造是浅拷贝（Shallow Copy）——直接复制指针变量的地址。（对于非指针的变量，实际上是拷贝的“值”，指针变量其实也拷贝的“值”，只是指针变量的“值”就是地址，所以会引发一系列问题）

  1. 浅拷贝的灾难：如果类管理了堆内存（new），两个对象指向同一块内存，析构时会导致 Double Free（双重释放）或野指针访问。
  2. 深拷贝（Deep Copy）：你必须手动开辟新内存，复制内容。
  3. 拷贝赋值运算符（operator=）：注意要处理自我赋值（if (this == &other) return *this;），否则释放自身资源时会把 other 的资源也干掉。

上述1～3，对应的具体代码

浅拷贝在析构时导致的问题：

#include <iostream>
#include <cstring>

class ShallowString {
public:
    char* data;
    
    ShallowString(const char* str) {
        data = new char[strlen(str) + 1];//开辟地址
        strcpy(data, str);//复制内容
        std::cout << "构造 data 地址: " << (void*)data << std::endl;
    }

    // 没有写拷贝构造，编译器自动生成浅拷贝：
    // ShallowString(const ShallowString& other) : data(other.data) {}

    ~ShallowString() {
        std::cout << "析构 data 地址: " << (void*)data << std::endl;
        delete[] data;  // ① 第一次释放 ok
    }
};

int main() {
    ShallowString s1("Hello");
    ShallowString s2 = s1; // 浅拷贝：s2.data = s1.data（指向同一块内存）

    // 程序结束时：
    // 先析构 s2 -> delete[] 内存 (第一次释放，成功)
    // 再析构 s1 -> delete[] 同一块内存 (第二次释放，触发 Double Free 崩溃！)
    return 0;
}

显示定义拷贝函数，使用深拷贝：

#include <iostream>
#include <cstring>

class DeepString {
public:
    char* data;
    
    DeepString(const char* str) {
        data = new char[strlen(str) + 1];
        strcpy(data, str);
        std::cout << "构造 data 地址: " << (void*)data << std::endl;
    }

    // 深拷贝构造函数：重新分配内存
    DeepString(const DeepString& other) {
        data = new char[strlen(other.data) + 1]; // 开辟新内存
        strcpy(data, other.data);                // 复制内容
        std::cout << "深拷贝 data 地址: " << (void*)data << std::endl;
    }

    ~DeepString() {
        std::cout << "析构 data 地址: " << (void*)data << std::endl;
        delete[] data; // 此时 s1 和 s2 指向不同内存，各删各的，安全
    }
};

int main() {
    DeepString s1("Hello");
    DeepString s2 = s1; // 调用深拷贝

    // 析构时：s2 释放 0x2000，s1 释放 0x1000，互不干扰
    return 0;
}

#include <iostream>
#include <cstring>

class AssignString {
public:
    char* data;
    
    AssignString(const char* str) {
        data = new char[strlen(str) + 1];
        strcpy(data, str);
    }

    // 错误版本的赋值运算符：没有检查是否自己赋值给自己
    AssignString& operator=(const AssignString& other) {
        std::cout << "赋值操作，准备释放自身: " << (void*)data << std::endl;
        delete[] data;                         // ① 释放了 this 的内存，这一步是必要的，否则会导致内存泄漏
        
        std::cout << "试图拷贝 other: " << (void*)other.data << std::endl;
        data = new char[strlen(other.data) + 1]; // ② 重新分配
        strcpy(data, other.data);                // ③ 复制内容
        return *this;
    }

    ~AssignString() { delete[] data; }
};

int main() {
    AssignString s("World");
    
    // 重点来了：自己赋值给自己
    s = s; 
    
    // 执行流程分析：
    // 1. delete[] data -> 释放了 s 自己的内存
    // 2. strlen(other.data) -> 由于 other 就是 this，此时 this->data 已经是野指针（已被释放）
    //    访问野指针 -> 未定义行为（绝大多数情况会读取到乱码或直接 Segfault 崩溃）
    return 0;
}

Type a = b; //这种写法不是“赋值运算”，它叫拷贝初始化（Copy Initialization），底层调用的是拷贝构造函数。

移动构造函数

移动构造函数（Move Constructor，C++11）：性能革命的根源

移动语义解决的是“临时对象”的昂贵拷贝问题。它的核心逻辑是“资源窃取”，而不是复制。

  • 右值引用（&&）：移动构造接受 Class(Class&& other)，它将 other 的指针直接“偷”过来，然后把 other 的指针置为 nullptr（或重置为默认状态）。
  • noexcept 的重要性：强烈建议将移动构造声明为 noexcept。因为 STL 容器（如 std::vector）在重新分配内存时，为了强异常安全保证，如果移动构造不是 noexcept，它会宁愿选择昂贵的拷贝构造，也不会调用移动构造，导致你的优化失效。
  • 移动赋值：同样遵循“释放自身旧资源 -> 窃取对方资源 -> 重置对方”。（请你结合代码为我讲解）

关于noexcept：做说明符（Specifier），写在函数声明处，告诉编译器和调用者“本函数承诺不抛出异常”。

void func() noexcept;          // C++11 起
void func() noexcept(true);    // 等同于上面
void func() noexcept(false);   // 等同于不写，可能抛异常

关于vector的移动构造，这里必须深入到 STL 源码的决策逻辑。

std::vector::resize() 或 push_back() 导致扩容时，本质是 “分配新内存 -> 转移旧元素 -> 释放旧内存”。C++ 标准为 vector 规定了 “强异常安全保证”（Strong Exception Guarantee）：如果扩容失败（比如内存不足抛出 bad_alloc），原 vector 必须保持原样，不能丢失任何数据。

这里的分水岭来了：

如果移动构造是 noexcept：vector 愉快地执行 “移动转移”（O(1) 指针交换）。即使后续操作失败，旧内存已经完全迁移，符合安全逻辑。
如果移动构造 不是 noexcept（即可能抛异常）：vector 会拒绝使用移动构造，转而调用昂贵的 “拷贝构造”（Copy）。为什么？因为拷贝如果失败（抛异常），旧数据还完好无损地停在旧内存里，可以回滚。而移动如果移动到一半抛异常，旧对象已经被撕碎（指针被偷走），数据永久丢失，无法回滚。

一个具体的例子

#include <iostream>
#include <vector>
#include <cstring>

class MyString {
private:
    char* data_;  // 指向堆内存的指针
    size_t len_;  // 字符串长度

public:
    // 1. 普通构造函数
    MyString(const char* str = "") : len_(strlen(str)) {
        data_ = new char[len_ + 1];
        strcpy(data_, str);
        std::cout << "[构造] 申请了堆内存: " << (void*)data_ << std::endl;
    }

    // 2. 拷贝构造函数 (深拷贝)
    MyString(const MyString& other) : len_(other.len_) {
        data_ = new char[len_ + 1];
        strcpy(data_, other.data_);
        std::cout << "[拷贝构造] 深拷贝, 新内存: " << (void*)data_ << std::endl;
    }

    // 3. 析构函数
    ~MyString() {
        if (data_) {
            std::cout << "[析构] 释放堆内存: " << (void*)data_ << std::endl;
            delete[] data_;
            data_ = nullptr;
        }
    }

    // 为了观察，加一个打印函数
    void print() const { std::cout << (data_ ? data_ : "null") << std::endl; }
};

对于移动构造函数本质就是，让自己的对象的指针指向使用other对象指针指向的值，然后将other对象的指针重置

// 4. 移动构造函数 (C++11)
MyString(MyString&& other) noexcept 
    : data_(other.data_), len_(other.len_) { // 第一步：偷走对方的指针和长度
    
    other.data_ = nullptr; // 第二步：切断对方的“所有权”（重置）
    other.len_ = 0;
    
    std::cout << "[移动构造] 窃取资源, 窃取后原指针: null" << std::endl;
}

C++在一定情况下会默认生成移动构造函数，在有默认移动构造函数的时候，触发方式如下：

int main() {
    MyClass a;
    MyClass b(std::move(a));
}

  1. 拷贝构造函数（Copy Constructor）
  2. 拷贝赋值运算符（Copy Assignment）
  3. 移动赋值运算符（Move Assignment）
  4. 析构函数（Destructor）
class MyClass {
public:
    ~MyClass() {}  // 我写了个空析构函数（甚至没做任何事）
    // 没有写拷贝构造、拷贝赋值、移动构造、移动赋值
};

int main() {
    MyClass a;

}

也就是说，通常在没有移动构造函数的时候，它会退化为拷贝构造函数。

析构函数

析构函数负责释放对象生命周期内获取的所有资源（内存、文件句柄、锁等）。

C++ 标准规定：析构顺序严格是构造顺序的逆序。

  1. 先执行当前类析构函数体（你写的代码）
  2. 按声明逆序销毁成员对象
  3. 最后调用父类析构函数。
#include <iostream>

// 用于充当“成员对象”的类
class Member {
public:
    Member(const char* name) : name_(name) {
        std::cout << "  [Member] " << name_ << " 构造" << std::endl;
    }
    ~Member() {
        std::cout << "  [Member] " << name_ << " 析构" << std::endl;
    }
private:
    const char* name_;
};

class Base {
public:
    Member m_base{"Base成员"}; // 成员变量
    Base() { std::cout << "Base 构造函数" << std::endl; }
    ~Base() { std::cout << "Base 析构函数（开始释放基类资源）" << std::endl; }
};

class Derived : public Base {
public:
    Member m_derived{"Derived成员"}; // 派生类成员变量
    Derived() { std::cout << "Derived 构造函数" << std::endl; }
    ~Derived() { 
        std::cout << "Derived 析构函数（开始释放派生类资源）" << std::endl; 
    }
};

int main() {
    std::cout << "=== 开始构造 ===" << std::endl;
    Derived d;
    std::cout << "=== 开始析构（离开作用域） ===" << std::endl;
    return 0;
}

上述析构函数在默认情况下会得到如下输出：

=== 开始构造 ===
  [Member] Base成员 构造      // 1. 基类成员先构造（因为基类先构造）
Base 构造函数                  // 2. 基类构造函数体
  [Member] Derived成员 构造    // 3. 派生类成员构造
Derived 构造函数               // 4. 派生类构造函数体
=== 开始析构（离开作用域） ===
Derived 析构函数（开始释放派生类资源） // 5. 先执行派生类的析构函数体
  [Member] Derived成员 析构    // 6. 逆序销毁派生类成员（后声明先析构）
Base 析构函数（开始释放基类资源）       // 7. 执行基类析构函数体
  [Member] Base成员 析构       // 8. 逆序销毁基类成员

由于继承了父类，所以先调用父类构造函数，构造父类成员变量；然后再调用自己的构造函数，构造自己的成员变量；并且由于自己和父类都有另一个类作为类型的成员变量，所以在自己的构造函数开始前，会默认调用对应类的构造函数。于是关于构造呈现出上述输出结果。

对于析构而言也是类似的，只是顺序是反的，先销毁派生类，再销毁父类。

虚析构函数

析构函数通常要设置为虚函数，否则在一些情况下会出现内存泄漏

一种典型的析构函数导致的内存泄露是：

#include <iostream>
using namespace std;

class Base {
public:
    ~Base() { cout << "~Base()" << endl; } // 非虚析构
};

class Derived : public Base {
public:
    ~Derived() { cout << "~Derived()" << endl; }
};

int main() {
    Base* p = new Derived();
    delete p; 
    // 输出只有：~Base()
    // 因为 Base 的析构非虚，delete 时只调用 Base 的析构，Derived 的析构未执行！
    return 0;
}

修复办法：只需将基类析构函数声明为 virtual ~Base() {}，delete p 时就会先调用 ~Derived()，再调用 ~Base()，完美释放资源。

离散数学

群论

群的定义：

$G$是非空集合，假如定义在$G$上的二元运算$ * $（乘法），满足下面四条公里，则代数结构$(G,*)$即群：

  1. 封闭性，$\forall a,b \in G, a*b \in G$
  2. 结合律，$\forall a,b,c \in G, (ab)c = a(bc)$
  3. 单位元，$\exists e \in G, \forall a \in G, e * a = a * e = a$
  4. 逆元，$\forall a \in G,\exists b \in G, a * b = b * a = e$，其中$e$是单位元，可以记$b = a^{-1}$

注意：

  1. 封闭性通常已包含在“二元运算”的定义中（即运算结果仍在集合内），但单独作为一条公理列出也是常见且完全合理的写法。所以当说明乘法是二元运算之后，不描述封闭性也可以
  2. 只有封闭性和结合律，称为半群（只能正向堆积）。
  3. 半群基础上加上单位元，即幺半裙（可以什么都不做）。
  4. 再幺半群基础上加上逆元，就有了群（拥有了“后悔药”和“解方程”的能力）。

群的性质：

  1. 唯一性定理
  • 一个群的单位元是唯一的
  • 每个元素的逆元是唯一的
  1. 消去律
  • 左消去$a * b = a * c, b = c$
  • 右消去类似
  1. 完备性
  • $\forall a,b \in G$，方程$a * x = b$总有唯一解$x = a^{-1} * b$（像整数集中$2x = 1$就是不可解的，实际上整数集也不是群，除非重新定义乘法）
  1. 逆元运算规则
  • $(a * b)^{-1} = b^{-1} * a^{-1}$
  1. 幂运算推广
  • 定义$a^0 = e,a^{n+1} = a^n * a$，则：$a^m * a^n = a^{m+n}$，$(a^m)^n = a^{mn}$
  • 注意：在群不满足交换律的情况下$(a * b)^n \ne a^n * b^n$

子群定义：设$(G, * )$是群，$H$是$G$的非空子集。若$H$在相同的运算下，也满足群的四条公里，则$H$是$G$的子群，记作$H \le G$。

平凡子群：任何群$G$都有两个平凡子群$G$和${e}$，其他子群，称为非平凡真子群

  • 代表性的例子，整数加法群$(Z,+)$中所有偶数的集合可以得到子群、所有3的倍数的集合也可以

陪集定义：设$H \le G,\forall a \in G$

  • 左陪集：$aH = {a* h| h \in H}$
  • 右陪集：$Ha = {h* a| h \in H}$
  • 注意：陪集不一定是一个新的群，除非$a \in H$，它通常是一个集合，反应的是$H$在原始群空间的一次“平移”或“投影”

陪集的性质：

  • 等势性：映射$h -> a* h$是一个双射，即每一个陪集的大小（势）都严格等于子群$H$的大小（$|aH| = |H|$）
  • 分割性：任意两个陪集，要么完全重合，要么毫不相交，即$\forall a,b \in G$，$aH=bH$和$aH$与$bH$相交为空，有且仅有一个成立；（这也意味着，所有左陪集构成了群的一个完全划分）
  • 如果群是阿贝尔群，则同一个元素对应的左、右陪集完全一样；否则通常不一样；

拉格朗日定理：

  • 陪集的个数称为是$H$在$G$中的指数，记做$[G:H]$
  • 对于有限群$G$，有$|G| = [G:H]|H|$（因为$H$对应的陪集将$G$划分为了若干等份，每一份的大小都是$|H|$）
  • 另一种等价的表述是，“元素阶整除群阶”，对于$|G| = 6$，子群大小只能是$1,2,3,6$中的一种，不可能是$4,5$

元素的阶：设$G$是一个群，$a\in G$，若存在正整数$a^n = e$，则这样的最小的正整数$n$就是元素$a$的阶，如果不存在的话阶是无穷大，记做$|a|$或$ord(a)$；

群的阶：$G$是群，则其元素的个数即群的阶，若有无限个，则阶无限大，记做$|G|$

循环群：若群$G$中存在至少一个元素$a$使得$G$中的每个元素都可以写成$a$的整数幂$a^n,n \in Z$，则$G$被称为循环群；

  • 无限循环群，群中非零元的阶是无限大的；
  • 有限循环群，群中非零元的阶不是无限大的；

注意：

  • 循环群可能不止有一个生成元
  • 整数幂，包括负数幂$-1$，对应的是取逆元，从而能够依次定义负数幂

对称群：

  • 设$X$是一个非空集合，由$X$到它自身的一个双射称为一个置换；（例如$X = {1,2,3}->{3,2,1}$，可以记做置换$(1 3)$代表$1->3->1$，$2$省略了是自己映射到自己；
  • $X$上所有这样的置换作为元素，构成的集合，再次基础上定义映射复合运算，就一定会构成一个群，即对称群；

注意：

  • 若$|X| = n$，则称为n次对称群，记做$S_n$
  • $|S_n| = n!$
  • 只要$n \ge 3$，$S_n$就是非阿贝尔群

置换的相关性质

  • 对换：若置换只交换两个元素，则称为对换
  • 定理1:所有置换都可以分解成若干个对换的复合映射
  • 定理2:置换分解成对换的结果不是唯一的，但是奇偶性是唯一的
  • 分解成奇数个对换的置换称为奇置换，分解成偶数个对换的置换称为偶置换

一个典型的置换的映射复合运算是(1 2)(1 3) = (1 3 2)，置换是从右向左考虑（左结合），得出(1 3 2)的方法是依次考虑输入1、2、3的最终结果（1->3->3 2->2->1 3->1->2）

置换群：对称群的子群就是置换群；

散列表线性探查

散列表线性探查：

  • index = (h(key)+i)%TableSize (i = 0,1,2,3…)
  • 实际上就是哈希函数计算出一个初始下标发现已经有元素了，就依次向后移动直到找到一个空位；

对应的基本操作：

（1）插入

从 h(key) 开始，逐个检查槽位，遇到第一个 空 就放进去。

（2）查找

从 h(key) 开始，逐个对比键。
如果匹配 → 找到。
如果遇到空槽 → 说明该键不存在（停止查找）。

⚠️ 注意：这是查找的终止条件，但如果处理不当删除，就会出大问题。

（3）删除（最需要留意的）

绝对不能直接把元素物理删除（置空）！
因为如果置空，查找时遇到这个空槽就会误以为后面的元素不存在了，导致查找失败。
正确做法：使用“墓碑”（Tombstone）标记。即删除后，将该位置标记为已删除（Deleted），而不是空。插入时可以覆盖墓碑位置，查找时遇到墓碑则跳过继续查。

希尔排序过程

为什么要使用希尔排序？

可以把希尔排序理解为“改进版的插入排序”。直接插入排序在数据基本有序时效率极高，但数据杂乱无章时移动次数太多。希尔排序的核心思想就是：通过“增量（步长）”将序列分组，在组内进行插入排序，让数据先“大范围”地粗略排好，最后再进行一次全局的插入排序。

希尔排序的核心步骤：

  1. 选定增量（步长）：通常取数组长度的一半作为初始增量（gap = n/2），之后每次减半，直到 gap = 1。
  2. 分组与排序：将相隔 gap 个位置的元素视为同一组，对每组分别进行直接插入排序。
  3. 缩小增量：将 gap 减半（gap = gap / 2），重复步骤 2。
  4. 最终排序：当 gap = 1 时，整个数组视为一组，执行最后一次普通的插入排序。此时数组已基本有序，移动次数极少，排序完成。

最小生成树

最小生成树：在无向连通图中，找到一棵树，让它连接图中所有的顶点，且所有边的总权重之和最小。

求最小生成树

Prim算法：

  • 核心思想：把图想象成两个集合——已选顶点集合 U 和 未选顶点集合 V-U。算法每次都从“连接这两个集合”的所有边中，挑出权重最小的那条边，并把对面那个新顶点拉进 U 里。
  • 执行过程（类似升级版的Dijkstra）：
  1. 任选一个起点（比如顶点0），把它加入 U，此时树根就有了。
  2. 维护一个数组 dist[]，记录每个未选顶点到当前树（U）的最小直接距离。
  3. 循环 V-1 次：每次从 dist[] 中挑出最小值对应的顶点 u，把 u 和那条边收入生成树。
  4. 新顶点 u 加入后，更新它所有邻居的 dist 值（如果邻居到 u 的距离比之前到树的距离更小，就更新）。

Kruskal算法：

  • 核心思想：直接把图中所有的边按权重从小到大排序。然后从最小的边开始遍历，如果这条边连接的是两个不同的连通分量（即加入后不会形成环），就把它加入生成树；否则直接扔掉。
  • 执行过程：
  1. 将所有边 (u, v, w) 按 w 升序排序。
  2. 初始化：每个顶点自成一个独立的连通分量（共 V 个）。
  3. 从小到大依次取边：用并查集（Union-Find）判断 u 和 v 是否已经在同一集合里。
  4. 若不在同一集合，则合并这两个集合（Union），并将该边加入生成树；若在，则跳过（防止成环）。
  5. 直到加入了 V-1 条边，算法结束。

最短路径

Bellman-Ford算法：

  1. 初始化：dist[起点] = 0，其余为 INF。
  2. 外层循环：重复执行 V - 1 次（V 为顶点数）。因为最短路径在没有负环的情况下，最多只包含 V-1 条边。
  3. 内层松弛：每次循环，遍历图中所有的边 (u, v, w)。如果 dist[u] + w < dist[v]，就更新 dist[v] = dist[u] + w。
  4. 检测负环（关键绝活）：第 V 次再遍历所有边，如果发现还能继续松弛（dist[u] + w < dist[v]），说明图中存在负权环（走一圈路径权值反而变小），此时最短路径无解（负无穷），算法报错。

注意：

  1. 思想类似于，依次考虑只能走一条边的时候，起点到各个点点最短距离、然后2条边的时候、3条边的时候…最终V-1条边，此时就得到了起点到各个点的最短距离
  2. 特殊情况是在V次时再进行遍历，如果出现了距离进一步减小，说明图中有负环，则不存在最短路径（通过负环可以把到所有点的距离都刷成负无穷）
  3. 内部循环每次都遍历图中所有的边，是简单但有效的操作

性质：

  • 单源最短路径，支持检测负权
  • 适合稀疏图，因为只内部只需要遍历边，点多一些无所谓；

Floyd算法

  1. 初始化：构建距离矩阵 dp[i][j]，直接相连的填权值，自己到自己填 0，其余填 INF。
  2. 三层循环（顺序绝对不能错）：
    for k in range(V):      // 枚举中转点（必须最外层）
    for i in range(V):  // 枚举起点
        for j in range(V): // 枚举终点
            if dp[i][k] + dp[k][j] < dp[i][j]:
                dp[i][j] = dp[i][k] + dp[k][j]

Flody算法的思想：“动态规划” + “中介中转”。它的视角是：如果要从 i 到 j，无非两种情况——要么直接走，要么经过某个中间节点 k 中转更近。算法穷举所有顶点作为中转站，不断更新距离矩阵。

性质：

  • 多源最短路径
  • 适合稠密图，因为时间复杂度是$O(V^3)$
