LLM并行与多模态加速调研

LLM并行

数据并行（Data Parallelism）

数据并行是最常用的分布式训练策略，遵循 SPMD（Single Program Multiple Data）模型。它将输入数据沿 batch 维度切分，每个 GPU 持有完整的模型副本，处理不同的数据分片。前向和后向计算在各 GPU 上独立进行，每层产生的梯度通过集合通信（All-Reduce）在所有 GPU 间聚合，用于优化器更新。

根据模型参数在各设备间的共享策略（引入共享因子 $F$，$1 \le F \le W$，$W$ 为设备数），数据并行分为三种形态：

  • 全复制（Full Replication，$F=1$）
    即经典数据并行。每个 GPU 都持有全部模型参数、梯度和优化器状态。代表实现：PyTorch DDP、Horovod。通信方式为 All-Reduce 聚合梯度，通常将梯度分桶以重叠通信与计算。优点是实现简单、通信模式规整；缺点是内存冗余严重，无法容纳超大模型。

  • 全分片（Full Sharding，$F=W$）
    模型参数、梯度和优化器状态按参数维度切分到所有 GPU 上，每个设备只保存 ($1/W$) 的模型状态。计算前通过 All-Gather 收集所需参数，计算后通过 Reduce-Scatter 聚合梯度并丢弃非本地的部分。代表实现：

    • ZeRO-3（Zero Redundancy Optimizer Stage 3）：对每个参数进行分片，通信量为全复制的 1.5 倍，但内存消耗最低。
    • FSDP（Fully Sharded Data Parallel）：以模块为单位分片参数，提供更易用的 API，并采用 Reduce-Scatter 替代 All-Reduce 以降低通信量。
    • Sharded Weight Update：同样按参数分片，但重点在于冗余参数更新计算的去重。

  • 混合分片（Hybrid Sharding，$1 < F < W$）
    将设备排列为$N \times M$网格，沿$N$维度分片模型参数，沿$M$维度复制。这样在内存节省和通信开销之间提供灵活折中。代表实现：

    • MiCS：使用 All-Gather 收集分片参数，All-Reduce 聚合梯度。
    • FSDP 同样支持混合分片，将 All-Reduce 优化为 Reduce-Scatter，降低通信量。

数据并行通信量主要受模型参数量和梯度大小影响，全分片虽大幅降低内存，但通信开销较高，因此实践中常结合张量或流水线并行共同使用。

张量并行（Tensor Parallelism）

张量并行又称层内模型并行，将每个 Transformer 层（如 MLP 和 Self-Attention）的参数张量沿多个维度切分到不同 GPU 上，从而将单层计算分布化。通信的是中间激活张量（尺寸通常小于参数/梯度），但通信无法与计算重叠，因此要求极高带宽（通常限制在同一个节点内）。

根据切分的维度数量，分为：

  • 1D 张量并行（Megatron-LM）
    针对 MLP 和 Attention 中的两个参数矩阵，第一个按列切分，第二个按行切分。每个模块的输入和输出在各 GPU 间复制，每次前向和反向各引入一次 All-Reduce。这是最经典的实现，易于使用但在多节点扩展时通信压力大。

  • 2D 张量并行（Optimus）
    借鉴 SUMMA 和 Cannon 二维矩阵乘法算法，将输入和参数张量同时在两个维度上划分，相比 1D 可降低通信量和内存冗余，但实现更复杂。

  • 2.5D 张量并行（Tesseract）
    基于 2.5D 矩阵乘法（改进了 Cannon 算法的效率），在 2D 基础上增加一层设备分组，进一步减少不必要的通信，适用于更大模型。

  • 3D 张量并行
    采用 3D 并行矩阵乘法算法，在三维设备网格上均匀划分线性操作，实现完美的负载均衡，但通信模式和实现难度最高。

张量并行通常与数据并行、流水线并行组合为 3D 并行，是 Megatron-LM 等框架的基础。

流水线并行（Pipeline Parallelism）

流水线并行又称层间模型并行，将模型按层切分成多个阶段（Stage），每个阶段分配到一组 GPU 上。阶段间仅需传递中间激活张量，通信频率低，适合跨节点（低带宽）扩展。

核心问题是流水线气泡（Bubble）和内存不平衡，以下技术针对这两点进行优化：

气泡减少调度

  • GPipe：采用“填-排”（Fill-Drain）调度，一次性注入所有微批次，先全前向再全反向，气泡较大。
  • 1F1B（PipeDream）：每个微批次前向完成后立即调度其反向，减少气泡，在异步场景下效果好。
  • Interleaved 1F1B（Megatron-LM）：为每个 GPU 分配多个流水线阶段（Looping placement），进一步降低气泡，但增加通信和峰值内存。
  • Chimera：引入双向流水线，两个方向并行，用权重复制换取气泡降低。
  • Zero Bubble：将反向计算分为激活梯度和参数梯度两部分，用 1F1B 调度前向和激活梯度，气泡中填入参数梯度计算，实现零气泡（但峰值内存增加）。
  • TeraPipe：沿序列维度拆分微批次，在 Token 级流水化，但基于 GPipe 调度，内存开销大。
  • DynaPipe：针对可变长输入的多任务训练，动态调整微批次大小并预规划通信，降低气泡。
  • Tessel：自动搜索最优流水线调度策略。

内存平衡

  • BPipe / MPress：运行时将激活张量从高负载 GPU 传输到低负载 GPU（D2D 交换），结合重计算降低峰值。
  • Chimera / Hanayo：通过双向或波状流水线为每个 GPU 分配对称阶段，均衡内存消耗。
  • V-Shape：将模型分为两倍于设备数的阶段，反向放置，在峰值内存和气泡间折中。
  • mCAP：基于增量剖析，按峰值内存均匀划分阶段。
  • AdaPipe：对不同阶段采用自适应重计算策略，并基于 1F1B 自适应划分以平衡计算。

流水线并行常与数据并行结合（如 DAPPLE、Varuna），并可通过重计算进一步降低内存。

序列并行（Sequence Parallelism）

随着上下文窗口扩展至百万 tokens，超长序列导致激活内存线性增长和 Attention 计算呈 $O(n^2)$ 复杂度。序列并行将输入沿序列维度切分到多个 GPU，每个 GPU 处理一部分 token，复制模型参数，常与张量/流水线并行结合。

核心挑战与方案

  • Ring-based 方法：
    通过环状通信传递 Key/Value 张量，逐步计算 Attention。

    • Ring Self-Attention：基础环状实现，依次传递 K 和 V。
    • DistFlashAttn：传输 KV 块，利用 FlashAttention 内核并平衡计算（用 later tokens 填充空闲）。
    • Megatron Context Parallel：结合 FlashAttention，消除因果掩码带来的冗余计算，通过对称交换平衡负载。
    • Striped Attention：非连续均匀分配 token 子集，解决负载不均。
    • BurstAttention：在每 GPU 上用 FlashAttention，双缓冲重叠通信与计算。
    • Blockwise Ring Attention：分块计算，降低内存。
    • WallFacer：先分组复制 Q 和 KV，用多个环状 P2P 通信，最后 ReduceScatter 输出。

  • Head-splitting 方法：

    • DeepSpeed-Ulysses：沿注意力头维度切分（而非序列），通过 All-to-All 转换维度，天然负载均衡，且可无缝接入 FlashAttention，但并行度受限于头数（尤其 MQA/GQA）。
    • USP / LoongTrain：将两者结合，组织 2D 网格，先 All-to-All 切换维度，再 Ring Attention 计算，LoongTrain 还引入 Double-Ring-Attention 充分利用跨节点带宽。

  • 动态切换（DSP）：根据计算阶段（如 DiT 中的多维 Transformer）动态选择并行维度。

序列并行能有效降低激活内存，但需小心设计通信与计算重叠。

专家并行（Expert Parallelism）

专家并行专为 MoE（Mixture-of-Experts） 模型设计。MoE 包含多个专家网络（FFN）和一个门控网络，每个 token 由门控路由到 Top-K 专家。专家并行将不同专家分布到不同 GPU 上，通过 All-to-All 通信交换 token 和专家输出。

基础框架

  • GShard：首次将 MoE 扩展到分布式 Transformer，专家分布在各 worker，使用 All-to-All 通信。
  • Switch Transformer：采用 Top-1 路由，最大化计算效率。
  • DeepSpeed-MoE：引入共享专家，并将更多专家置于深层，平衡通信与精度。

与 3D 并行结合

  • DeepSpeed-TED：将数据、张量、专家并行统一，MoE 参数按 tile 切分，避免优化器内存尖峰，并提出重复 token 丢弃和激活检查点优化通信。
  • Tutel：自适应并行切换，可在每轮迭代动态切换策略且无额外开销。

计算优化

  • Megablocks：实现块稀疏矩阵乘法（Block Sparse Matmul），支持不同专家输入大小不同，避免 token 丢弃和填充浪费。
  • ScatterMoE：融合分组 GEMM 和散读/写操作，降低 Top-k（$ (k \ge 2 )$）时的内存占用。

通信优化

  • Tutel / FasterMoE：沿专家容量或专家维度拆分张量，重叠计算与通信，节点内聚合小消息再跨节点交换。
  • PipeMoE：根据工作负载建模，自适应寻找最优分区数以最小化训练时间。
  • ScheMoE：在 All-to-All 前加入数据压缩，并模块化调度通信和计算。
  • Lina：优先调度 All-to-All 而非 AllReduce，以提升带宽利用率，并微操作调度。
  • Janus：采用数据为中心范式，保持数据不动而移动专家（基于参数服务器），使用非阻塞拉取和预取。

负载均衡

  • FasterMoE：基于前一轮工作负载，将热门专家动态广播到其他 GPU（影子专家），分散负载。
  • SmartMoE：两阶段搜索最佳专家放置，在线切换保持负载均衡。
  • FlexMoE：复制重专家到多设备，通过扩展/收缩/迁移调整放置。
  • Prophet：系统化搜索最优专家放置，并分层调度隐藏开销。

模型-系统协同

  • TA-MoE：拓扑感知路由，通过辅助损失使路由匹配底层拓扑，兼顾模型精度。

专家并行是 MoE 模型训练的核心，其通信开销（All-to-All）和负载不均问题始终是优化焦点。

可能的热点问题

  1. 自动化并行策略选择：针对不同的模型架构（密集/稀疏）和硬件配置（异构集群），如何自动搜索最优的混合并行策略（数据、张量、流水线、序列并行的组合），避免依赖专家经验的手工配置。
  2. 异构硬件的自适应并行：集群中混合不同代际、不同厂商的加速器（如A100/H100/AMD/TPU）及不均匀的网络带宽，如何实现自动化的负载均衡和并行策略适配，最大化整体吞吐量。
  3. 长序列训练的超长上下文并行优化：随着上下文窗口扩展至百万tokens级别，如何进一步优化序列并行（如Ring Attention、DeepSpeed-Ulysses等）以线性降低激活内存，并解决负载不均和通信开销问题。
  4. MoE模型的负载均衡与动态专家放置：混合专家（MoE）模型中，热门专家导致的计算/通信负载不均问题，如何通过动态设备放置、专家复制或拓扑感知路由来优化。
  5. MoE训练中的All-to-All通信优化：专家并行依赖All-to-All通信，在跨节点场景下开销极大，如何通过重叠计算与通信、微操作调度或数据压缩来降低影响。
  6. 计算-通信重叠的细粒度调度：如何在算子级别（如矩阵乘法与AllReduce的分解调度）实现计算与通信的最大化重叠，包括优先级调度、分解调度、张量分块等策略。
  7. 拓扑感知的集合通信算法合成：针对具体集群拓扑（如Rail-optimized、Torus、Clos等），自动合成最优的集合通信算法（AllReduce/AllGather/ReduceScatter），而非依赖NCCL等库的通用预定义算法。
  8. 网内聚合（In-Network Aggregation）在并行训练中的规模化部署：如何将SHARP、SwitchML等可编程交换机上的梯度聚合技术从原型推进到大规模生产部署，并与现有并行训练框架无缝集成，从而降低数据并行中的通信流量。
  9. 零气泡流水线调度与内存平衡的协同优化：如何在消除流水线气泡（Zero Bubble）的同时，平衡各阶段的激活内存消耗，避免因内存不均而限制微批次数量。
  10. 多模型异构时的并行调度优化：多模型异构的情况，例如强化学习人类反馈（RLHF）训练涉及Actor、Critic、Reward、Reference四个模型，如何通过异构模型放置（分离/交错策略）和阶段调度来最大化GPU利用率。又比如多模态大模型（MLLM），其通常包含文本、视觉等多种模态的编码器，其结构和计算模式差异巨大，需要设计异构的并行策略。
  11. MoE模型的EP优化：针对混合专家（MoE）模型的专家并行（EP），研究如何在运行时无缝切换EP和TP，以适应动态请求；或优化EP在跨Pod通信时的开销。
  12. 自适应并行推理：让模型根据问题复杂度，自主决定是否以及如何分解和并行执行子任务。这能避免为简单问题付出高昂的并行开销，是提升推理效率的前沿方向。

多模态加速

一、模型层面的方法

模型层面的效率优化着眼于架构拓扑本身，旨在从源头减少冗余计算，使网络结构天然具备高效特征提取与跨模态交互的能力。

1. 模态专用编码器的演进与专业化

针对视觉模态，效率导向的编码器经历了从轻量化卷积到分层注意力，再到状态空间模型的演进。早期工作如MobileNet和EfficientNet利用深度可分离卷积和复合缩放规则来降低浮点运算量，但这些方法受限于局部感受野。随后，MobileViT和CoAtNet等混合架构试图结合卷积的归纳偏置与Transformer的全局建模能力，以求在效率和表现力之间取得折中。随着Vision Transformer（ViT）的兴起，全局自注意力的二次复杂度成为瓶颈，Swin Transformer通过引入移位窗口注意力机制，将复杂度降为线性，重新引入了局部先验。更进一步，最新的研究如Vision Mamba彻底抛弃了注意力机制，采用双向状态空间模型（SSM），以线性复杂度实现全局感受野，同时保持了恒定的推理内存占用，为高分辨率图像处理提供了全新的效率范式。

针对文本模态，效率优化主要围绕突破Transformer的二次复杂度瓶颈。从BERT和ViT开始，全局注意力成为标准配置，但处理长序列时成本急剧上升。为了解决这一问题，Longformer和BigBird引入了稀疏窗口或全局-局部注意力机制，将复杂度降至线性水平；Linformer则基于注意力矩阵的低秩特性，通过投影进行近似压缩。在当前的解码器-only大模型（如LLaMA）背景下，为了支撑无限长的多模态上下文，Linear Transformer和TextMamba等架构重拾了RNN的线性推理内存优势，同时保留了Transformer可并行训练的特性，使模型能够在不爆显存的情况下，维持海量的对话历史和视觉描述。

针对音频模态，效率路径从早期的VGGish和CNN14这类依赖2D卷积处理频谱图的方式，转向了自监督学习范式。Wav2Vec 2.0和HuBERT采用轻量卷积前端提取局部特征，配合Transformer后端捕获全局上下文，极大地提升了下游任务的泛化能力且减少了对标注数据的依赖。Audio Spectrogram Transformer（AST）进一步对齐了视觉范式，将频谱图切分为块（patch）进行全局注意力建模，简化了设计空间。然而，对于长时音频，全局注意力依然吃力，Audio Mamba等最新模型再次引入选择性状态空间模型，以严格的线性复杂度处理声学流，使得高保真音频能够无缝地作为原生token集成到大型语言模型中，奠定了实时全感官理解的基础。

对于热成像、深度图和时序数据等非典型模态，效率设计呈现出“混合”与“轻量化”的收敛趋势。热成像因对比度低，TarDAL采用双流拓扑解耦目标语义与噪声，而FW-SAT则利用局部窗口注意力限制计算范围。深度感知因测量稀疏，Lite-Mono将轻量卷积用于局部补全，仅对关键区域施以Transformer以建立全局尺度一致性。时间序列则因采样不规则和依赖极长，Informer引入ProbSparse稀疏注意力来近似全局上下文，而最新的Mamba和Liquid-S4系列则利用线性递归建模连续时间动态，以线性复杂度处理长周期预测，彻底解决了Transformer在时序任务上的内存爆炸问题。

2. 统一多模态编码器：从双流融合到自回归统一

相较于维护多个独立分支，统一编码器试图通过一个共享的计算核心（如联合Transformer主干）处理异构token，将效率定义为功能的集约化。早期的UNITER和ViLT丢弃了笨重的目标检测器或卷积前端，直接将图像块和文本词元嵌入同一个Transformer进行浅层交互，证明了参数共享本身就是一种高效的跨模态理解方式。FLAVA和AV-HuBERT则将这一范式扩展至音频和视频，通过联合掩码预测，利用跨模态协同训练作为隐式正则化器，显著减少了总预训练计算量。最激进的统一策略体现在自回归模型（如Emu、Unified-IO 2和UGen）中，它们将所有模态（图像、文本、音频、动作）离散化为统一的序列，并优化统一的“下一词元预测”目标函数。这种设计将序列建模确立为多模态的通用接口，使得条件生成与跨模态迁移在单一的效率框架下得以无缝实现。

3. 结构稀疏性与条件计算：将容量与计算解耦

结构稀疏性通过将动态路由嵌入模型架构，实现了“万亿参数、千亿计算”的愿景。早期的VLMo和LMoE为了解决跨模态干扰，引入了模态感知的混合专家（MoE）路由，将图像和文本词元导向各自独立的专家网络（FFN），实现了表征的解缠。然而，这种刚性划分存在局限性。Uni-MoE等最新框架演进为统一语义路由，专家被所有模态共享，并根据词元级别的语义复杂度动态激活——复杂推理词元调用更多专家，简单纹理块仅调用最少专家，使稀疏性由静态规则进化为响应式的内容感知机制。更进一步的LEO-MINI和Flex-MoE将视角投向了硬件约束，它们不再追求最大容量，而是通过分层路由或混合秩专家来适应严格的延迟或内存预算，创造出能够动态调整激活参数集的“任意预算”架构。

4. 结构化解码：为生成引擎建立固定容量的通道

在多模态大模型生成阶段，解码器若直接处理高分辨率、变长的特征图，将招致不可承受的二次方开销。结构化解码通过在感知编码器和语言解码器之间插入一个可学习的瓶颈层来解决此问题。Flamingo引入的Perceiver-style重采样器，利用固定数量的潜在查询向量与视觉输入进行交叉注意力，将时空特征压缩为恒定数量的视觉词元。BLIP-2则提炼了这一原则，采用轻量级的Q-Former作为语义桥梁，主动将密集的编码器输出“蒸馏”为紧凑且与文本对齐的词元集合。这两种方法本质上都将跨模态交互限制在了一个固定容量的有界通道中，使生成引擎彻底摆脱了输入像素规模的束缚。

5. 模块化适配：结构解耦实现低成本迁移

模块化适配旨在不触碰冻结的预训练主干的前提下，通过插入轻量级模块实现模态对齐和任务微调。这主要分为两个结构层面：一是跨模态连接器，如LLaVA中简单的线性投影层或MiniGPT-4中的多层感知机，它们作为最小化的物理桥梁，将视觉特征映射到语言模型的嵌入空间；二是内部旁路微调，如LoRA（低秩适配），它在Transformer层的内部引入低秩分解矩阵作为可训练旁路，仅用原始参数极少的分量就能让模型内部推理适应新模态。最新的MMA和PaLM2-VAdapter甚至构建了即插即用的适配器银行，可根据不同任务动态切换。这类策略重新定义了效率：将能力的横向扩展与基座模型的维护彻底解耦，实现了极严格显存预算下的可扩展对齐。

二、算法层面（Algorithm-Level Efficiency）：压缩信息流以调制“如何计算”

在架构固定的前提下，算法层面的效率侧重于运行时（Runtime）的信息流压缩，通过减少数据冗余和降低算术精度来降低计算与内存负担。

1. Token压缩与选择性计算：精准剔除冗余视觉词元

由于视觉词元存在严重的空间冗余，Token压缩成为加速多模态Transformer最关键的手段。

无需训练的压缩方法直接利用预训练模型的固有属性进行推理时剪枝。早期手法通过分析视觉编码器内部的注意力图或显著性图来剔除低重要性词元。Redundancy-aware方法更进一步，通过测量特征之间的相关性或余弦相似度，合并掉彼此重叠的冗余表示。为了对抗一次性剪枝带来的信息突变，先进的ST3和Multi-stage Drop等方法引入了分层自适应或渐进式剪枝策略，在网络的不同层逐步减少词元数量。Fit-and-Prune甚至将词元选择建模为约束优化问题，以找到信息损失最小的剪枝子集。代表性系统如ST3和LLaVolta证明，即使剪掉超过70%的视觉词元，模型的推理精度依然能够得到保持，这充分说明了非语义冗余的巨大占比。

需要重新训练的压缩方法则内化了压缩目标。PuMer、TokenPacker和P-Mod等方法引入了轻量级的可学习评分网络，其重要性得分与下游任务损失函数及L1稀疏正则项协同优化。通过端到端的训练，模型学会了在执行具体任务（如VQA或图像描述）时，主动丢弃无用词元。此外，基于池化或聚类的框架（如VisionZip）则将语义相似的词元抽象为更紧凑的潜在嵌入，从根本上缩短序列长度。课程学习策略（如LLaVolta）在训练过程中逐步降低token预算，迫使模型适应极度压缩的表示空间，从而在极高的压缩率下依然能保持语义保真度。

2. 结构性剪枝：永久性精简冗余参数

与Token级动态剪枝不同，结构性剪枝旨在移除模型中冗余的层、神经元或注意力头。早期的多阶段框架对视觉和文本分支进行联合维度缩减。EfficientLLaVA将剪枝表述为泛化感知搜索问题，利用小规模代理数据自动选择注意力层和MLP层的最优剪枝组合。UPop则提出了统一渐进剪枝，跨模态动态分配剪枝比例，在微调过程中逐步精炼掩码（Mask），确保高压缩率下收敛稳定性。最前沿的MANU引入了模态感知神经元剪枝，其核心在于识别并移除那些仅负责跨模态冗余信息的神经元，从而在压缩模型的同时，提升了视觉与语言表示的“解缠度”（Disentanglement），使存留的参数肩负更清晰的语义职责。

3. 量化：降低数值精度以换取带宽与能耗

量化通过将高精度浮点数（FP32）映射为低比特整数（如INT8）来压缩模型体积和加速计算。公式上，它涉及缩放因子和零点，将实值张量映射到离散网格中。

训练后量化（PTQ）因无需重训而易于部署，但面临视觉与文本特征统计分布差异巨大的独特挑战。针对此，Q-VLM和MBQ引入了模态感知校准，利用敏感度感知的混合精度分配，对波动剧烈的视觉通道分配较高比特宽，而对稳定的文本通道分配较低比特。StaMP则针对激活值量化，通过序列变换抑制异常激活值（Outliers），防止其在低比特推理时导致量化崩溃。

量化感知训练（QAT）主要用于4比特以下的极端压缩场景。QSLAW在指令微调阶段集成了模态感知预热和可学习步长，使网络权重在训练时就主动适应量化噪声。通过将量化参数与模型权重联合优化，网络学会了在高度离散化的空间内依然保持视觉与语言之间微妙的语义对齐。

4. 缓存与重用（KV Cache）：打破上下文长度与显存的枷锁

在自回归生成中，键值（KV）缓存占用随序列长度线性增长，是系统吞吐量的绝对瓶颈。

动态驱逐与压缩策略主动识别并移除缓存中的冗余词元。VL-Cache引入了模态感知剪枝，利用注意力指标激进地驱逐冗余的视觉块，同时保护关键的文本上下文。Elastic-Cache和LOOK-M则更进一步，利用注意力熵区分语义“锚点”（需保留）和重复模式（可压缩），前者通过锚点合并实现高保真压缩。CSP通过解耦自注意力和交叉注意力通道来稳定剪枝过程。FastCache和AirCache引入检索增强型压缩，将不频繁访问的“冷”缓存状态卸载至CPU内存或磁盘，而将“热”状态保留在GPU高带宽内存中，在无限上下文愿景与有限物理显存之间构建起分层存储架构。

时间与跨会话重用则利用多模态信号的时序连贯性分摊计算成本。在机器人或视频流场景中，VLA-Cache会识别并冻结静态背景词元，仅针对动态变化区域重计算。Inf-MLLM通过监测“注意力鞍点”来维持流式输入的长程依赖。最具突破性的是MPIC和Cache-of-Thought，它们支持位置无关的缓存重用，通过将KV状态投影到可转移的空间或检索语义相关的历史状态，允许不同用户、不同请求之间共享昂贵的预填充（Prefill）计算结果，显著降低首次词元生成时间（TTFT）。

5. 知识蒸馏（KD）：将大模型的表征与行为迁移至轻量学生模型

知识蒸馏按迁移内容的不同深度分为三个层次。

预测层蒸馏是最基础的实现，通过最小化教师和学生模型输出逻辑分布（软标签）之间的KL散度来迁移知识。PromptKD利用基于提示的监督，能在无标注数据下蒸馏任务先验；FDBPL引入区域感知的二值提示，将精细的空间决策信号迁移给学生。

表示层蒸馏超越了最终结果，致力于对齐中间层的注意力图、词元嵌入或关系矩阵。CLIP-KD和TinyCLIP通过直接特征匹配压缩视觉-语言主干。DSMID利用动态调度同步特征演化进度；SF-CLIP通过掩码蒸馏强制学生聚焦于显著空间区域。在架构迁移方面，mm-Mamba利用渐进对齐，成功将Transformer架构的稠密知识蒸馏进了线性复杂度的状态空间模型（SSM），实现了架构代际间的知识传承。

行为层蒸馏是目前最深刻的范式，它传递的是教师模型的思维链（CoT）、推理分解或偏好判断。Skywork R1V引入自适应推理长度监督，平衡思维链的完整性与简洁性。VPD（视觉程序蒸馏）针对结构化任务，将显式的程序性推理轨迹蒸馏给学生。LLaVA-MoD则应用排名蒸馏，让学生模仿教师对多个候选答案的相对偏好排序，而非仅仅拟合绝对文本概率，这使得紧凑模型也能具备类似大模型的审慎、偏好驱动的推理能力。

6. 提示学习与推测解码：优化输入逻辑与突破串行生成瓶颈

参数高效提示学习将任务适配转化为输入空间的连续优化问题。Prefix Tuning固定了模型权重，仅在每一层Transformer前添加可训练的任务特定键-值前缀，以此引导注意力机制。CoCoOp在此基础上进化，将静态提示转变为动态、实例感知的提示，使条件词元根据输入图像特征实时演化，仅更新极少量（<1%）参数即能获得高度专业化的性能。

推测解码是破解自回归生成内存带宽受限（Memory-bound）困境的关键。它引入一个轻量级的草稿模型（或提示条件头），廉价地连续生成多个候选词元，随后由完整的目标模型在单次前向传播中并行验证这些候选词元。在多模态语境下，Spec-VLA将这种机制引入具身智能（VLA模型），通过放宽接受标准来加速动作序列生成，在不降低任务成功率的前提下，突破了自回归无法并行的物理极限。

7. 运行时稀疏性：根据输入复杂度动态调节计算图

运行时稀疏性利用样本难度方差实现按需分配计算。

层跳跃与动态深度策略观察到多数视觉词元在网络浅层就已趋于稳定。Skip-Vision基于累积注意力分数剔除低影响词元及其KV条目。D-ViTDMETR应用强化学习在每层做出二进制的“执行或跳过”决策，轻松降低一半以上的浮点运算量。MoLe-VL和λ-MoD将深度视为连续路由维度，基于词元熵或时空显著性学习稀疏激活路径。

早退与自适应终止将固定深度网络转化为动态级联。DeeCap证明，对于简单的图像描述实例，浅层语义已足够。MuE形式化了收敛监测机制，当跨模态表示趋于饱和时即刻终止计算。CREMA和CAPEEN将早退决策融入训练循环，将深层知识蒸馏至浅层出口，确保无论终止于哪一层，输出质量都保持稳定。

注意力稀疏与合并用于缓解全局注意力的二次成本。ETESparse施加固定局部窗口，而LoRA-Sparse动态地仅对Top-K个最相关的键计算注意力，大幅缩小了自注意力矩阵的规模。此外，模型合并（如TIES-Merging）和Token级缓存合并（如LLaVA-PruneMerge）分别展示了在参数空间和激活空间聚合相似表征以提升运行效率的潜力。

三、系统层面（System-Level Efficiency）：资源编排以决策“在何处与何时计算”

系统层将效率从算法和硬件解耦，上升到基础设施调度的高度，这是实现规模化部署（Serving）的关键。

1. KV缓存管理与服务系统

在生产环境中，KV缓存管理直接决定了系统吞吐量和最大并发用户数。Lee等人的性能剖析研究表明，长上下文场景的端到端延迟主要由内存带宽和内核启动开销主导，而非计算强度。为此，现代服务引擎集成torch.compile、CUDA Graph执行和FlashAttention，通过内核融合最小化调度开销。针对多模态特有的提示长、共享前缀多的特点，Gemini 1.5等系统引入了前缀缓存，将相同系统提示的KV状态持久化，避免重复预填充。FastCache构建了轻量级的KV缓存压缩框架，通过智能驱逐策略动态调整缓存大小，在服务层面实现了每秒请求数（QPS）的显著提升。

2. 边缘-云协同计算

为了应对边缘设备算力有限与云端传输延迟高的矛盾，系统层面引入动态卸载策略。Cloud-Device Collaborative框架根据实时网络状况和设备剩余电量，动态切分模型计算图——浅层特征提取在边缘端完成，深层推理卸载至云端。EdgeCloud针对视频分析任务，设计了分布式流水线，允许边缘节点预处理并压缩视频流，大幅减少上行带宽占用。MoA-Off则针对多模态LLM提出了异构模态感知卸载，将视觉编码等带宽密集型任务放在本地，将语言生成等计算密集型任务发送至云端，通过协同优化最小化端到端延迟。

3. 延迟感知的作业调度

为了保障服务质量（QoS），系统调度器需感知模型异构性。DivPrune利用多样性驱动的视觉词元剪枝，在作业排队阶段预估不同请求的复杂度。RServer提出了重叠编码（Encoding）与预填充（Prefill）阶段的调度策略，通过流水线并行掩盖通信延迟。Amazon Nova等工业级技术报告展示了在生产环境中，如何根据请求的紧急程度、模型大小和当前集群负载，动态分配GPU实例和推理优先级。

4. 硬件-软件协同设计（Co-Design）

这是打破传统“先训练后部署”流程的颠覆性范式。工作负载特征映射要求首先刻画多模态算子（如Cross-Attention、MLP）的计算密度和带宽需求。计算密集型大MLP被路由至高算力张量核心（TPU/GPU），而带宽受限的归一化或逐元素融合操作则被分配给近存计算单元，最大限度地减少数据搬运这一主要能耗源。联合架构-硬件搜索（如Harmonic-NAS）则将硬件反馈（延迟、能耗、峰值内存）直接嵌入网络架构搜索循环，在物理预算约束内寻找模型结构（模态主干、融合网络）和部署参数（量化位宽、批处理大小）的帕累托最优解。

5. 联邦学习（Federated Learning）

在医疗、个人传感器等隐私敏感场景中，系统瓶颈在于同步巨大主干的通信开销。通信高效微调方案（如FedCLIP和PFedPrompt）冻结重多模态基座，仅交换轻量适配器或提示向量，将单轮通信负载从GB级降至MB级。为应对客户端设备异构（有的有摄像头，有的只有IMU），FedCMR和PmcmFL引入缺失模态鲁棒机制，通过对齐共享原型库来聚合异构知识。针对传感器丰富的环境，FDARN和MCARN采用双编码器分离模态无关（共享）与模态特定（私有）特征，仅聚合共享组件，既降低了上传维度，又通过物理隔离加强了隐私保护。

四、高效MLLMs（多模态大模型）的集成案例

作为MAS框架的关键验证场，高效MLLMs展示了三者的垂直集成。在模型层面，早期的BLIP-2和LLaVA通过轻量适配器实现训练效率，而最新的NVILA则通过“缩放-然后-压缩”视觉编码器从源头降低token量，MoE-LLaVA利用专家混合将容量与计算解耦。在算法层面，LOOK-M在不微调的情况下压缩80%的KV缓存，Spec-VLA利用推测解码打破动作生成的串行瓶颈。在系统层面，MPIC实现了跨请求的提示感知缓存共享，EdgeShard则支撑了异构硬件上的协同推理。最终，这些技术融合的趋势指向了自适应效率（如MiniCPM-V），即模型能够自主决定“计算什么、如何计算、何处计算”，使效率成为智能计算的内在自调节属性。

五、总结与核心洞见

综上所述，多模态加速绝非简单的“压缩或剪枝”，而是一场贯穿架构定义（Model）、信息流调制（Algorithm）和物理资源编排（System）的全栈革命。三者之间存在强依赖关系：模型层定义了效率的上限（如稀疏路由降低了激活参数数量）；算法层逼近并微调这一上限（如量化将理论算力转化为实际硬件利用率的提升）；系统层则确保理论加速在真实物理约束（内存墙、功耗墙、通信墙）下得以忠实兑现。未来，克服统一Tokenization、跨模态泛化鲁棒性、隐私-效率-效用三难困境（Trilemma）等挑战，将更加依赖这种深度的跨层协同，最终推动多模态智能从“中心化的庞然大物”进化为“无处不在的适应性智能体”。
