深度学习

梯度下降

  1. 基本原理
  2. BGD
  • 含义
  • 优点：1）梯度精确，下降方向稳定（在优化曲面上，其轨迹最为平滑、稳定） ；2）理论收敛次数较少（线性收敛，SGD是次线性收敛）；3）可充分收敛到极小值，当曲面有唯一极小值或为凸函数时，BGD几乎能够精确地收敛到极小值；4）可以利用并行计算；
  • 缺点：1）每步计算成本较高，需要扫描整个数据集，存在冗余计算（相同的样本）；2）容易卡在鞍点与尖锐极小值点（精确梯度在鞍点处几乎为0，让更新停滞；尖锐极小值点对应泛化能力较差），缺乏跳出能力；
  1. SGD
  • 含义
  • 优点：1）单步极快，实际训练速度快；2）总计算量较小，要达到同样的精度$\epsilon$，SGD的时间复杂度是$O(\epsilon)$，而BGD时间复杂度是$O(N\epsilon)$；3）可以利用噪声逃逸，摆脱鞍点和尖锐局部极小值点；
  • 缺点：1）梯度估计噪声大，损失函数下降过程中存在剧烈波动；2）由于梯度的随机性和固定的学习率，尽管概率论保证其会朝极小值点收敛但是无法像BGD一样精确地完成收敛，最终一般呈现出在极小值附近震荡；3）学习率调节极具挑战，需要精心设计衰减策略；
  1. MiniBatch GD
  • 含义
  • 优点：1）计算效率相比BGD更高，可以并行化实现，是可接受的；2）梯度估计相较于SGD噪声小很多，更新方向更稳定，减小了震荡容易逼近精确值；3）相较于BGD梯度估计仍然带有部分噪声，具有逃逸能力；
  • 缺点：1）batch_size、学习率的超参数需要精心设计；2）仍然属于SGD、BGD之间的一种权衡，噪声的存在具有两面性，可能无法达到最优；
  • 选取batch_size与epoch的关系：batch_size增加，epoch一般也应该增加；
  • 原因：1）补偿减小的更新步数（1个epoch的更新次数 = 样本总数/batch_size）；2）补偿减小的探索能力（batch_size增大对应的噪声减小，跳出鞍点、尖锐极小值的能力减弱，用更多的epoch来补偿）；3）配合大学习率衰减（batch_size增大一般可以等比例大增大学习率，然后采用学习率衰减的策略，长epoch有利于学习率衰减）
  1. 动量随机梯度下降
  • 含义：指数加权移动平均
  • 优点

自适应优化器

  1. Adagrad
  • 特点：1）每个参数有自己的学习率；2）用s累计参数对应梯度中的更新量的平方；3）更新时学习率除以平方；
  • 优点
  • 缺点
  1. RMSprop
  • 特点：在Adagrad基础上，将s更新改为指数加权移动平均，从而减小遥远梯度的影响
  1. Adam
  • 特点：1）RMSprop+Momentum，采用了RMSprop相同的逐元素的学习率缩放策略，此外更新时的梯度值使用动量随机梯度下降得到，对应的值分别称为一阶矩$m_t$和二阶矩$v_t$；对应指数加权移动平均的衰减率为$\beta_1,\beta_2$；2）再实际使用之前要用$m_t/(1-\beta^t_1),v_t/(1-\beta^t_2)$进行偏差修正；因为训练初期一、二阶矩偏向0会导致模型参数发生巨大的跳动，后期修正分母会逐渐趋于1；

Batch Normalization

  1. 操作过程 线性变换之后 激活函数之前
  2. 解决的问题：内部协变量偏移
  • 协变量偏移：机器学习中训练集和测试集的输入分布不一致，导致模型泛化困难。
  • 内部协变量偏移：对于网络的任意一层，它接收的是前一层输出的特征（即它的“输入”）。当前面层的参数被梯度更新后，特征输出就会改变——这意味着该层的输入分布一直在变。
  1. 目的：为了让网络在每一层都保持相近的分布
  2. 深入理解
  • 正规化手段 强行分布 均值0 方差1
  • 使得激活函数输入值处在合理区间 防止梯度爆炸或梯度消失（对于sigmoid激活函数，如果输入落在远离0的饱和区，该项导函数值非常小，会导致该激活函数以前的参数在计算对应梯度值时变得非常小，发生梯度消失）

为什么BN层一般用在线性层和卷积层之后，而不是放在非线性单元之后

  1. BN设计的初衷是为了主要是为了控制激活函数输入的分布，放在后面无法控制该输入，输入仍然会跑到饱和区导致梯度消失之类的问题；
  2. BN 的标准化操作（减均值、除标准差）针对的是近似对称、无界的分布效果最好。线性层输出根据中心极限定理近似高斯分布，对它们进行归一化会产生一个更加稳定的分布

BN层计算均值的时候计算多少次

  1. 假设[b,c,h,w]计算bhw次，针对每个通道有一层BN
  2. BN层有2c个参数（归一化后带一个缩放、平移的参数，$\gamma,\beta$）

监督学习——生成式 v.s. 判别式

  1. 生成式模型：利用贝叶斯公式对联合概率（类条件概率、先验概率）建模，最终得到某类数据的分布模型，间接地再得到后验概率，用于分类；
  • 典型代表 1 2 3 4 5
  • 优点 在模型假设数据分布与真实分布接近的情况下收敛较快，可以用于生成数据
  • 缺点 计算资源量大
  1. 判别式模型：直接尝试对后验概率建模，不关心数据的实际分布，而是尝试学习到不同类别数据的边界条件，从而实现分类；
  • 典型代表：1 2 3 4 5
  • 优点 计算资源量大
  • 缺点 不能生成数据
  1. 关系
  • 都是为了得到后验概率
  • 生成式->判别式

L1正则化与L2正则化的区别与联系

  1. 联系：都是施加惩罚项，迫使模型使用更小的权重，从而降低方差

Dropout

  • Dropout层实现的方式（作用于前一层神经元的输出，伯努利分布采样0-1 mask矩阵，0对应丢弃上一层某个神经元；结果要除以1-p防止输出期望被系统性缩小(1-p)倍）

理解指定维度的操作很重要

切片语法

切片语法的作用：高效地在原始张量的基础上提取出所需 维度/索引 的数据

按照最一般的情况（5维张量）对应(批次，时间步，通道，高度，宽度)

x = torch.rand(2,5,3,16,16) #2个批次 5个时间步 3个通道 16*16的数据

常用符号之“:”

  1. 全选某维度的元素
    x_view = x[:,:,:,:,:] # 注意点1：x_view 与 x是共享内存的（切片操作默认得到的是视图，对应原始5维张量）
x_view = x[1,1,:,:,:] # 注意点2：整数索引会带来“降维”，这里得到的是torch.Size([3,16,16])的张量视图（对应x张量在第1批次、第1个时间步的样本）
  2. 选择某维度指定范围的元素（左闭右开）
    x_view = x[1,3:5,:,:,:] # 注意点3：时间步选取范围左闭右开对应实际索引是3~4，因此得到的张量形状是torch.Size([2,3,16,16])
x_view = x[1,:5,:,:,:] # 注意点4：如果指定范围前面省略默认从0开始，得到张量形状是torch.Size([5,3,16,16])
  3. 添加维度
    x_view = x[:,:,:,:,:,None] # 注意点5：等价于unsqueeze(5)，在最后插入一个新维度（索引从0开始）当然None也可以出现在起始维度（等价于unsequeeze(0)） 或者出现在中间 即使插入了新维度，默认得到的也是视图
  4. 步长采样
    x_view = x[:,::2,:,:,:] # 注意点6：在时间步维度上每2个索引采样一步，省略开始索引默认从0开始，因此采样到的是0 2 4，对应torch.Size([2,3,3,16,16])
x_view = x[:,1::2,:,:,:]# 注意点7：指定开始采样维度，采样得到的是1 3，对应torch.Size([2,2,3,16,16])
  5. 反向操作
    x_view = x[:,::-1,:,:,:] # 注意点8：“-”代表反向操作，反向操作时默认从“末尾索引”开始，到“开始索引”（0）结束
x_view = x[1,3:5:-1,:,:,:] # 注意点9：“-”可以搭配前面的多种操作使用，例如此处是对时间步维度选择指定范围之后再反向
  6. 省略操作
    x_view = x[...,:4,:4] # 注意点10：“...”代表范围内所有维度的所有位置都被选中，例子中操作的含义是保留所有批次、时间步、通道中样本的左上角4*4的部分

高级索引

整数张量/整数列表索引

  1. 使用torch.Tensor/NumPy数组
  2. 索引取得张量的维度是：高级索引数组（广播后，若有）的维数 + 未被高级索引覆盖的维数（这些维数由切片、省略号等保留）
  • 注意广播后的高级索引维度会被“提到最前面”，而不是插在原位置

eg1 没有广播的情况

import torch

x = torch.arange(24).reshape(2, 3, 4)  # shape (2, 3, 4)
i = torch.tensor([[0,1], [1,0]])        # shape (2,2)
j = torch.tensor([[1,2], [2,1]])        # shape (2,2)

# 索引：x[i, j]   # 第0轴用 i，第1轴用 j，第2轴不写（默认:）
# 实际等价于 x[i, j, :] 结果形状——广播：i 与 j 形状都是 (2,2)，广播后还是 (2,2)；保留轴：第三轴长度 4；结果形状 = (2,2) + (4,) = (2,2,4)

out = x[i, j]  # 实际等价于 x[i, j, :]
print(out.shape)  # torch.Size([2, 2, 4])

eg2 有广播的情况

x = torch.randn(5, 7, 3)        # (5, 7, 3)
idx1 = torch.tensor([0, 1]).reshape(2, 1)   # (2, 1)
idx2 = torch.tensor([0, 1, 2]).reshape(1, 3) # (1, 3)

out = x[idx1, :, idx2]          # 第0、2轴用高级索引，第1轴切片
# 广播 idx1(2,1) 与 idx2(1,3) → (2,3)
# 保留轴：第1轴长度 7
# 结果形状：(2, 3) + (7,) = (2, 3, 7) 高级索引的轴保留相对顺序，提到最前面来
print(out.shape)  # torch.Size([2, 3, 7])

eg3 单一维度上使用高级索引

x = torch.randn(5, 7, 3)        # (5, 7, 3)
idx = torch.tensor([[0,3],[2,4]]) # (2,2)

out = x[idx]                     # 只索引第0轴，其余轴全保留
# 广播形状：(2,2)
# 保留轴：第1轴 7，第2轴 3
# 结果形状：(2,2) + (7,3) = (2,2,7,3)
print(out.shape)  # torch.Size([2, 2, 7, 3])

上述维度变换的关系是：

  1. x的第0维会按照idx变成(2,2)的形状
  2. 对应有4个元素
  • out[0,0]<->idx[0,0]<->”0”，按照0索引到x[0]，即out[0,0]处为x[0]处的(7,3)形状的矩阵
  • out[0,1]<->idx[0,1]<->”3”，按照1索引到x[3]
  • out[1,0]<->idx[1,0]<->”2”<->x[2]
  • out[1,1]<->idx[1,1]<->”4”<->x[4]

注意，按照高级索引选取维度的规则，甚至存在这种让维度变多的情况
注意，与切片不同，一旦使用了高级索引得到的是副本而不是视图
高级索引可以和切片结合使用

补充：分支界限算法

  1. 思想：用于求解最优化问题，维护一个 “活结点表” ，起初只有根结点。算法不断从表中取出一个结点（成为当前扩展结点），生成它的所有孩子结点，再通过 约束函数 和 限界函数 检查哪些孩子结点可能包含最优。只有通过检查的孩子才会被插入活结点表，等待后续扩展。当活结点表为空时，算法结束，当前最优解就是全局最优解
  • 约束函数：排除不可行解（如背包超重）。
  • 限界函数：排除那些即使继续搜索也无法得到优于当前最优解的结点。
  1. 例子：0-1背包问题
  • 状态节点来自于对当前物品是否选择
  • 约束函数即节点扩展后当前背包是否超重
  • 界限函数（上界值）可以用分数背包估计：1）将物品按照价值重量比降序排列，扩展一个节点后针对剩余空间从当前可选物品开始按照分数背包的规则贪心拿取，填满背包时得到的就是上界（界限函数），如果该值小于当前最优值则该节点不能纳入活节点表（剪枝）

LLM并行

常见的并行策略：

  1. 数据并行（DP）：最基础，模型复制多份，分吃不同数据。
  2. 张量并行（TP）：拆解矩阵乘法。把一层网络切分到多张卡上算。
  3. 序列并行（SP）：配合TP使用，专门把LayerNorm、Dropout这些非矩阵运算按序列长度切分。
  4. 上下文并行（CP）：针对超长序列（如DNA、蛋白质序列）。
  5. 流水线并行（PP）：按层切分（GPU 1跑1-5层，GPU 2跑6-10层）。
  6. 专家并行（EP）：针对MoE（混合专家）模型。只激活部分专家，稀疏计算。

数据并行

核心思想：当你的模型能放进一张GPU，但数据量太大、训练太慢时，可以把模型复制到多张GPU上，每张卡处理不同的数据子集。最后同步所有卡的梯度来更新模型。

适用场景：模型能装入单卡，但是想用较大的Batch Size加速训练

在Pytorch中，梯度采用累加而非替代。因此可以使用多个Mini-Batch模拟一个比较大的Batch，分别进行前向传播和反向传播之后，统一再调用执行一次 optimizer.step()。这是单卡解决因为Batch Size较大而导致OOM的策略

在有多卡的时候可以采用，分布式数据并行（DDP）工作流，来解决上述问题

DDP 的标准执行流程如下：

初始化 ProcessGroup：建立进程间的通信握手，每个进程控制一张GPU，保存同一模型的一个副本
广播权重（Broadcast）：训练开始时，Rank 0 节点的模型权重被广播到所有其他节点，确保初始状态一致。
前向反向传播：每个节点在自己的数据子集上独立计算。
梯度归约（All-Reduce）：各节点的梯度被汇聚（求和或平均），通常在Rank 0完成，然后同步回所有节点。
参数更新：各节点使用同步后的梯度独立更新权重。

参考链接：

  1. PyTorch 分布式训练底层原理与 DDP 实战指南(https://cloud.tencent.cn/developer/article/2593964?policyId=1003)

张量并行（TP）

张量并行的基础概念：张量并行是一种将模型中的张量（多维数组或矩阵）沿特定维度分成若干部分，并在不同设备上并行计算的技术。这种技术可以有效解决单块GPU无法储存整个模型的问题，提高训练效率。

核心思想：将模型中的大张量（如权重矩阵）分解成多个小块，每个小块放置在不同的GPU上进行独立计算。在计算过程中，各GPU之间通过通信来交换必要的数据，以实现整体的计算目标。

典型的切分方式：

  1. 行并行：将权重矩阵按行切分，输入数据按列切分，然后在不同GPU上分别计算。
  2. 列并行：将权重矩阵按列切分，输入数据保持完整，同样在不同GPU上分别计算。

具体的例子：
假设我们有一个简单的线性层计算：Y = XA，其中X是输入数据，A是权重矩阵，Y是输出数据。

  1. 在行并行中，我们可以将A按行切分为A1和A2，X按列切分为X1和X2。然后，在GPU0上计算X1A1得到Y1，在GPU1上计算X2A2得到Y2。最后，将Y1和Y2相加得到最终的Y。
  2. 在列并行中，我们将A按列切分为A1和A2，X保持不变。然后，在GPU0上计算XA1得到Y1的一部分，在GPU1上计算XA2得到Y1的另一部分。最终，将两部分结果拼接起来得到完整的Y。

  1. Megatron-LM

序列并行（SP）

核心思想：序列并行的核心是沿序列维度（Sequence Dimension）切分输入，让多张GPU各自处理一个序列片段，从而突破单卡显存对序列长度的限制

为什么需要序列并行：

考虑Transformer中最典型的缩放点积注意力

$Attention(Q,K,V) = softmax(\frac{QK^T}{\sqrt{d_k}})V$

其中Q、K、V的size都是$[L,d_k]$（暂时不考虑Batch和多头），L是序列长度（包含的token数量），$d_k$是特征维度

那么$QK^T$实际上是一个size为$[L,L]$的张量，存储了序列中每一个Token对其他所有Token的关注分数。这是包含$L^2$个元素的中间张量，规模实际上很大。

  1. 通信与拓扑优化
  • 拓扑感知的并行策略：研究如何根据集群的物理网络拓扑（如NVLink、InfiniBand的层次化带宽）来优化并行策略。
  • 降低同步开销：研究能否不完全同步激活值来训练模型。
  • 零通信开销的序列并行（SP）：针对线性注意力等特定模型结构，设计几乎无通信开销的SP方法。
  1. 动态与自适应并行策略
  • 动态策略切换：研究如何根据输入序列的长度，动态地、在运行时切换最优的并行策略。
  • 自适应并行推理：让模型根据问题复杂度，自主决定是否以及如何分解和并行执行子任务。这能避免为简单问题付出高昂的并行开销，是提升推理效率的前沿方向。
  1. 推理阶段的并行优化
  • 自适应并行推理：让推理模型自主决定如何将一个复杂问题分解为可并行的子任务、以及启动多少并发线程。
  • 异构感知的自动并行化：针对由不同算力、内存和带宽设备构成的异构集群，自动搜索最优的并行策略。例如，AutoHAAP框架通过智能的搜索空间剪枝和负载均衡估算，能在异构环境下显著提升训练吞吐量。
  1. 系统与调度优化：宏观视角
  • 异构资源调度：探索如何在共享GPU集群中，通过时空复用等技术，高效调度混合的微调和推理任务。
  • 容错与弹性训练：研究如何在超大规模（数万GPU）集群中，通过高效的检查点、恢复和弹性调度，保证训练的长期稳定性。
  1. 新型模型架构的并行策略
  • MoE模型的EP优化：针对混合专家（MoE）模型的专家并行（EP），研究如何在运行时无缝切换EP和TP，以适应动态请求；或优化EP在跨Pod通信时的开销。
  • 多模态大模型（MLLM）的异构并行：MLLM通常包含文本、视觉等多种模态的编码器，其结构和计算模式差异巨大，需要设计异构的并行策略。

eg：通信与拓扑优化

为什么需要通信与拓扑优化？

  1. 减少同步开销：研究发现，在张量并行（TP）中并非所有激活都需要完全同步。通过设计“通信感知架构”，可将TP通信量减少高达50%，且不显著损失精度。
  2. 协同调度优化：混合使用TP和流水线并行（PP）时，可设计更精细的协同调度来同时减少TP的通信开销和PP的“流水线气泡”。如STP方法通过将PP的前后向传播解耦为细粒度单元并重新编排，可将训练吞吐量提升12%-16%。

对应的方法例如，CAAT-Net，使用了部分通信的架构

传统TP中，每层计算后都需All-Reduce同步全部激活值。CAAT-Net打破了这一做法。它采用，通道分组与部分规约：它将一个层的输出通道分成两组，计算时只对其中一组进行跨设备的同步规约（partial channel-reduce）。未被同步的通道，其来自不同设备的部分直接被拼接（concatenate）起来作为输出。这一改动直接将TP通信量减少了高达50%，并且在7B参数的模型上测试，预训练精度几乎没有下降。

  1. 共享通道 (Shared Channels)：这部分通道在所有设备间进行同步（All-Reduce）。
  2. 私有通道 (Private Channels)：这部分通道不进行同步，每个设备各自保留自己计算出的结果。

这里的关键是引入了一个同步因子 (synchronization factor) p (0 < p ≤ 1)，它决定了共享通道所占的比例。当 p=1 时，就是传统的完全同步；当 p=0.5 时，则有一半的通道成为私有通道，通信量因此减半。

例如：

MLP层：假设输入X被分为X1和X2，权重B被分为B11, B21（设备1）和B12, B22（设备2）。经过“部分通道归约”后，两个设备的输出Z1和Z2会不同：

$Z1 = [Y1B11 + Y2B12, Y1B21] $
$Z2 = [Y1B11 + Y2B12, Y2B22] $
可以看到，$Y1B11 + Y2B12$ 这部分是共享的（经过了同步），而 $Y1B21 和 Y2B22$ 则是私有的。

数学上与一般的前向传播不在等价，但依然有效（实验证明的）的可能原因？

  1. 核心原因：大模型的“过度参数化”与鲁棒性，大规模语言模型（LLMs）的一个特点是过度参数化（Over-parameterization），即模型参数量远大于训练数据量，这为网络带来了强大的鲁棒性和容错能力。
  2. CAAT-Net正是利用了这一点。它引入的“部分同步”本质上是一种可控的、结构化的噪声。你可以把传统的完全同步看作是多位专家必须对每个细节都达成绝对一致；而3. CAAT-Net则是允许专家们在某些细节上（私有通道）保留己见，只需在关键结论上（共享通道）达成共识。
  3. 研究表明，只要控制好这种“分歧”的范围（即同步因子p≥0.5），大模型强大的冗余性就足以吸收这部分噪声，使其不会影响最终的判断（模型精度）。

进一步的研究方向

将边界扩展一下，不再局限在LLM并行

多模态加速，针对当下的world model

世界模型处理多种模态数据（文本、图像、视频、动作等），其内部不同组件（如视觉编码器、LLM）的计算模式各异。因此，需要有针对性的加速策略：

  1. 架构级加速：新的服务系统（如M*）将模型视为一个“组件图”，为不同组件（如Transformer、扩散模型）匹配最优的并行策略（如Paged Attention、CUDA-graph）。
  2. 推理级加速：专门为世界模型设计的加速方法，例如：
  • Fast-LeWorldModel：将传统的“一步步”预测改为并行预测，将动态模块耗时从31.4秒降至8.0秒。
  • WorldCache：通过智能缓存技术，区分处理变化平缓或剧烈的数据，实现近无损提速3.7倍。
  • Emu3.5的DiDA技术：将推理速度提升了20倍。
  1. 运行时系统：为实时交互场景设计的系统（如TeleFuser），支持流式推理、有状态会话和分布式GPU执行，以满足世界模型连续、低延迟的运行需求。

世界模型的并行规划与加速

将LLM并行训练的经验迁移到世界模型的推理与规划阶段，是极具价值的high-impact方向。
具体切入点：

  1. 动作前缀并行预测：借鉴Fast-LeWorldModel的思路，将“单步预测”改为“多步并行预测”。
  2. 梯度-based并行规划器：研究GRASP（Gradient RelAxed Stochastic Planner）等方法，利用世界模型的可微性，将状态视为优化变量进行并行规划。
  3. 模型分解与模块化：探索将复杂的世界模型分解为可并行执行的模块，或为Transformer、扩散模型等不同组件匹配最优并行策略。

游戏引擎在world model的应用：

最直接的是提供“确定性状态”作为训练数据（消除多模态歧义）
真实世界的像素数据（如视频）存在严重的混杂偏差（Confounding）：像素相同不代表状态相同（光照、天气变化）。
一般模型的数据数学形式是(x,y)，前者是图像像素级别的张量，后者是主观标注。
而游戏引擎提供的数据数学形式：(s,a,s_next,r)，s是精确的物理坐标、速度、质量矩阵。
这意味着游戏引擎提供的训练数据包含了底层的真值状态（Ground-truth State）。有了这个，世界模型的训练可以从“像素到像素”的端到端，退化为“状态到状态”的监督学习。
